# 동기화 반복 부하 개선 — 2026-10-08

## 변경 범위

Mac·iPhone 공통 동기화 코드만 개선했다. 데이터 형식·공유 폴더·과거 CSV 파일은 유지하며 삭제/마이그레이션하지 않는다.

- 전체 폴더의 경량 메타데이터 목록을 비교하고, 변경된 이벤트와 CSV만 읽고 검증한다. 크기·mtime 외에 inode·ctime(나노초 포함)을 비교해 동일 크기/수정 시각의 덮어쓰기도 감지한다.
- 성공한 동기화 배치만 처리 완료로 기록한다. 읽기/적용/발행 실패 및 취소 시에는 다음 확인에서 다시 처리한다. 수동 동기화는 전체 검증을 수행한다.
- 캐시에는 파일 메타데이터만 보관한다. 기존 100,000개 항목 제한을 유지하고, 삭제된 파일 정보는 다음 성공 배치에서 제거한다.
- CSV 기준 문서를 한 번에 모으지 않고 하나씩 읽어 처리한다. 로컬/원격 이벤트가 달라지면 충돌 판정이 달라질 수 있으므로 과거 CSV도 재검토한다.
- 변경 없는 확인에서는 이벤트 상태 재계산·CSV 재생성·내보내기 링크 교체를 생략한다. 날짜 변경 시에는 CSV를 갱신한다.
- 알림을 묶되 연속 알림 때문에 확인이 계속 뒤로 밀리거나 진행 중인 읽기가 취소되지 않게 했다. 진행 중 들어온 알림은 추가 확인 한 번으로 합친다.
- 보조 확인은 15초에서 시작해 변화가 없으면 30/60/120초로 늘리고 변경 알림·활성화 시 되돌린다. 기존 오류 재시도 지연도 유지한다.
- 비활성화 시 진행 중인 동기화 Task를 취소한다. 파일 탐색/읽기·문서 처리 사이에서 취소를 확인한다. 이미 실행 중인 단일 OS 파일 조정 호출은 반환될 때까지 기다릴 수 있다.
- 증분 확인 중 충돌/경고를 유지하되, 해당 CSV가 잘못된 내용으로 교체되면 오래된 충돌 선택지는 제거한다.

## 검증

- `swift test --build-system native --scratch-path /private/tmp/today-routine-tests`: 130개 테스트, 실패 0개.
- 변경 없는 내보내기 링크 갱신 회귀 테스트: 수정 전 실패, 수정 후 통과.
- 잘못된 CSV로 교체된 뒤 이전 충돌이 남는 회귀 테스트: 리뷰에서 발견, 수정 전 실패 확인 후 수정하여 통과.
- 처리 완료 전 재읽기, 손상 이벤트(크기/mtime 유지), 파일 삭제, 취소 후 재시도, 과거 CSV 순차 읽기 및 편집, 두 저장소 동기화, 충돌 선택, 경고 유지/해제, 알림 폭주와 비활성/재활성화 테스트 포함.

- Mac 및 iPhone 시뮬레이터 대상 최종 `xcodebuild ... build CODE_SIGNING_ALLOWED=NO`: 둘 다 `BUILD SUCCEEDED`.
- 로그: `/private/tmp/sync-final-tests.log`, `/private/tmp/sync-mac-final.log`, `/private/tmp/sync-ios-final.log`.

## 한계

위 시간은 로컬 임시 폴더에서의 비교이며 실제 iCloud/아이폰 CPU·배터리·메모리 감소율 측정이 아니다. 메타데이터 탐색 자체는 전체 폴더를 대상으로 한다. 메모리 캐시는 재실행 시 초기화되므로 첫 확인에서는 파일을 다시 검증한다. OS 동기화 알림 누락에 대비해 보조 확인을 유지한다.
