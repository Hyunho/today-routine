# iCloud 다운로드 대기 중 재처리 개선 — 빌드 50

## 재현 근거

빌드 48에서 CPU 37~45%, 메모리 약 105MB가 관찰됐다. 실행 스택은 과거 CSV 읽기/해석이었고 Sync 로그는 manifest.json, 변경 이벤트 JSON, baseline.json 등의 iCloud 다운로드 대기로 전체 동기화가 중단됨을 보였다. 전체 성공 뒤에만 메타데이터를 승인하는 방식 때문에 앞서 처리한 문서도 재시도마다 다시 읽었다.

## 변경

- 다운로드 대기를 별도 오류 유형으로 구분하고 준비된 이벤트와 영수증을 부분 배치로 반환한다. .icloud 자리표시자는 원래 파일의 논리 경로로 처리한다.
- 검증과 저장이 끝난 이벤트를 개별 승인한다. 이벤트 다운로드가 남아 있으면 CSV 해석은 보류해 불완전한 저널에 기반한 충돌 판정을 방지한다.
- CSV 처리가 끝나면 그 파일의 메타데이터와 처리 당시 저널 ID 집합 해시를 기록한다. 다른 파일이 대기/실패해도 진행 기록이 유지된다. 저널 상태 또는 CSV 파일이 바뀌면 다시 처리한다.
- 대기 CSV를 건너뛰고 나머지를 처리한다. 취소/오류로 처리하지 않은 파일을 성공으로 기록하지 않는다.
- 파일 알림·활성화·보조 타이머가 오류 재시도 대기 시간(2/5/15/60초)을 무시하지 않도록 한다. 명시적 수동 동기화는 우회할 수 있다.

## 테스트와 빌드

- 전체 코어 테스트 145개 통과, 버전 스크립트 테스트 3개 통과.
- 추가 회귀: 일부 문서 대기 후 완료 문서 건너뛰기, 저널 변경 후 재평가, 다운로드된 이벤트의 개별 승인, 대기 CSV와 별개인 CSV 적용, 누락 이벤트가 있을 때 CSV 적용 보류/복구, 재활성화·알림 폭주에서 재시도 간격 유지.
- Mac 개발 인증서 서명 빌드와 iPhone 시뮬레이터 대상 빌드 성공. 빌드 번호는 다른 작업의 49 다음인 50 사용.
- 코드 리뷰에서 차단할 결함 없음. 지적된 누락 이벤트 통합 시나리오 및 재시도 간격 테스트까지 추가했다.
