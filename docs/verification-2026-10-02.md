# 오늘의 루틴 iPhone 검증 기록

## 구현

SwiftUI / SwiftData, iOS 17 이상, 외부 패키지 없이 기기 저장. 오늘·계획·루틴·기록 네 탭과 기기 알림을 구현했다. 웹 버전 48의 그룹 안 시간순 정렬(미지정 마지막, 동률은 수동 순서·UUID)을 반영했다.

## 확인한 결과

- macOS 공유 저장소·도메인·알림 어댑터 테스트 20개 통과.
- iPhone 17e / iOS 27 시뮬레이터 UI 테스트: 생성·완료·종료·재실행·주간 집계, 빈 이름 검증, 저장 실패 입력 보존·재시도, 접근성 큰 글자에서 단계 완료·일감·타임블록 저장과 재실행 유지 통과.
- SwiftData 7종 모델 파일 재열기, 손상 파일 불변, 저장 오류 롤백, 반복 요일, 한국 자정과 월요일, 중복 완료 방지, 완료 취소, 단계 변경과 과거 데이터 보존, 연결 해제, 겹친 블록 허용 검증.
- 가짜 알림 센터로 권한 거부 시 저장 기능 유지, 허용 시 예약, 완료 날짜 취소, 다른 기능의 예약 보존 검증.
- 실제 시뮬레이터 UserNotifications 권한 허용, 미래 예약 생성 및 스위치 해제 시 0개 취소 확인. 전체 UI 테스트는 5개 통과(핵심 흐름 4개와 추가 시스템 알림 1개).
- 실제 디스크 공간을 소진하지 않고 저장 경계에 `fileWriteOutOfSpace` 오류를 주입했다. UI 테스트 전용 별도 저장소로 사용자 데이터와 분리했다.
- 큰 글자 밝은 화면과 긴 한글 제목의 어두운 화면 캡처를 검토했다. `screenshots/`에 보관했다.

## 리뷰 및 수정

별도 검토자가 전체 변경을 읽었다. 한국 자정 이후 앱 복귀 시 오늘 선택을 갱신하되 사용자가 고른 과거 날짜는 유지하도록 고쳤다. 과거 날짜는 현재 반복 요일·보관 상태와 관계없이 저장된 기록이 보이며 당시 이름을 표시한다. 입력 오류 알림이 편집 시트를 닫던 문제도 재현한 뒤 수정했다.

## 구현 중 판단과 영향

1. 승인된 전용 저장소와 구현 브랜치를 사용했다. 추가 worktree 격리는 없어 같은 폴더의 외부 수정과 분리되지 않는다.
2. 공통 모델·규칙은 macOS Swift Package로 검증하고 iOS 통합은 시뮬레이터로 검증했다. macOS 결과만으로 iOS 실행을 대신하지 않는다.
3. Documents 경로의 Finder 메타데이터로 서명 문제가 있어 호스트 테스트에 SwiftPM native 엔진과 `/private/tmp`를 사용했다. 향후 도구 버전이 바뀌면 빌드 옵션을 조정할 수 있다.
4. draft와 데이터 변경 코드를 작은 파일로 나눴다. 동작은 같고 소스 파일 수만 늘었다.
5. 과거 단계 이름은 저장 모델에 없으므로 현재 단계로 과거 상세를 재구성하지 않는다. 과거 완료와 당시 루틴 이름은 유지하지만 삭제된 단계 이름은 볼 수 없다.
6. 서명·실기기 알림 전달·배포·동기화는 승인된 범위에 맞춰 별도 확인 대상으로 남겼다. 시뮬레이터에서 통과해도 실기기 전달까지 보장하지 않는다.

리뷰에서 미룬 경미한 지적은 없다. 앱 아이콘과 스토어 배포용 자산은 포함하지 않는다.

## 실기기

아직 사용자 아이폰에 설치하지 않았다. Xcode에서 개발 팀과 Bundle Identifier를 설정하고 아이폰을 연결해 실행해야 한다. 실제 알림 전달은 이 단계에서 확인한다. iOS 17은 배포 최소 버전이며 이번 실행 검증 OS는 iOS 27이다.
