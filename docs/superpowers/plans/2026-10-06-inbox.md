# 수신함 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 오늘의 루틴에 루틴 알림과 RSS 글을 모아 읽고 저장하며 읽던 위치로 돌아오는 수신함을 추가한다.

**Architecture:** 독립 로컬 JSON 저장소에 구독·글·알림·위치를 보관한다. 피드 파서와 제한된 네트워크 클라이언트를 분리하고 MainActor 모델이 병합 및 UI 상태를 조정한다. 기존 알림 계획을 대기 기록에 연결하며 루틴 데이터베이스와 동기화 형식은 유지한다.

**Tech Stack:** Swift, SwiftUI, Foundation/XMLParser, URLSession, XCTest. iOS 17 / macOS 14. 외부 패키지 없음.

**Spec:** `docs/superpowers/specs/2026-10-06-inbox-design.md` (2026-10-06 사용자 승인)

## Global Constraints

- 첫 구독: `https://hyunho-feeds.pages.dev/99cf9e8a101b6d8561a2c2e9aebea93d/feed.xml`. 최초 한 번만 등록하며 삭제 후 재생성하지 않는다.
- 전체 / 루틴 알림 / 구독 글 필터와 나중에 읽기, 필터별 최상단 항목 복원. 한국어 UI 및 기존 청록색 스타일.
- 기기 간 수신함 동기화 없음. 기존 미커밋 변경 보존. 테스트는 독립 저장 경로와 가짜 네트워크 사용.
- HTTPS 피드 주소, 요청 제한 시간 20초, 수신 중 5 MiB 제한, 자동 갱신 간격 15분.
- 일반 글은 구독별 최신 500개, 일반 루틴 알림은 최근 90일. 저장 항목 보존.
- 알림은 예정 시각 기준 기록이며 OS 실제 전달로 표시하지 않는다. 앱 종료 중 수집, 일감 알림, RSS 푸시, 원문 본문 추출은 제외.

## Review Focus

- 구독 삭제 직후 도착한 네트워크 응답이 삭제한 구독·글을 되살리지 않아야 한다 (Task 3).
- 구독 삭제·보관 한도 정리 후에도 저장한 글과 원문 출처가 유지되어야 한다 (Task 1).
- 용량 부족이나 손상 파일로 루틴 앱이 열리지 않거나 기록이 덮어써지면 안 된다 (Task 1, 5).
- 날짜 없는 글이 새로고침마다 최상단으로 올라가거나 같은 GUID의 글이 중복되면 안 된다 (Task 2, 3).
- 수신함에 머무는 동안 새 글이 도착하거나 대상 행이 제거되어도 위치 복원이 반복 점프를 만들면 안 된다 (Task 5, 6).
