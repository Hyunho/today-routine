# 일감을 Apple 미리 알림으로 통일

작성일: 2026-10-09
상태: 구현 전 설계 검토

## 목적과 범위

사용자는 앱 내부에서 별도로 일감을 관리하는 기능을 없애고 Apple 미리 알림 연동만 남기기로 했다. 루틴의 반복 규칙, 단계, 실행 기록과 타임블록은 앱에서 계속 관리한다. 일감의 제목, 메모, 날짜와 완료 상태는 Apple 미리 알림이 원본이다.

이번 전환은 내부 일감의 일반 사용 경로 제거, 기존 데이터 이전, 오늘 화면 집계와 연결 기능 정리를 포함한다. 기존 내부 일감 데이터를 즉시 삭제하거나 저장 스키마에서 TaskItem을 제거하지 않는다. 기존 저장소와 동기화 파일을 읽는 호환 계층으로만 유지한다.

## 확인한 현재 구조

- PlanningView에는 미리 알림과 내부 일감 목록이 함께 있으며 상단 추가 버튼은 TaskDraft를 생성한다.
- TodayView는 내부 일감을 목록, 시간 배치, 완료/미완료 집계에 사용한다. 미리 알림은 선택 날짜 마감 항목으로 이미 따로 표시한다.
- FocusSessionView의 내부 일감 집중 완료는 SwiftData의 완료 상태를 변경한다.
- TimeBlock.linkedID는 UUID이며 내부 일감 또는 루틴을 가리킨다. EventKit 식별자는 문자열이므로 그대로 대체할 수 없다.
- 내부 일감은 StoreSyncBridge를 통해 기기 간 동기화된다. 미리 알림은 현재 별도 복사본을 동기화하지 않는다.
- AppleRemindersAccess.save는 저장 결과 식별자를 반환하지 않고 새 항목의 완료 상태를 지정하는 기능도 없다. 이전 기능에는 별도의 인터페이스가 필요하다.

## 사용자 화면

### 일감

탭 이름은 일감을 유지한다. 목록에는 선택한 Apple 미리 알림 목록의 항목만 표시한다. 상단 추가 버튼도 AppleReminderEditor를 연다. 대상 목록은 편집 화면에서 확인하고 선택할 수 있다.

연결하지 않았으면 연결 안내와 연결 버튼을 표시한다. 권한 거부, 선택 목록 없음, 쓰기 가능한 목록 없음은 서로 구분한다. 작성할 수 없는 상황에서 내부 일감으로 대체 저장하지 않는다. 기존 조회, 편집, 완료 전환, 새로고침 기능을 유지한다.

### 오늘

내부 일감을 목록, 시간 배치, 남은 개수와 완료 개수에서 제외한다. 해당 날짜 마감 미리 알림 표시와 원본 완료 전환은 유지한다. 날짜가 없는 미리 알림은 일감 탭에서 조회한다. 루틴과 캘린더 표시 기준은 변경하지 않는다.

### 기존 일감 이전

설정에 기존 일감 이전 화면을 둔다. 남은 데이터가 있으면 일감 화면에서도 해당 화면으로 안내한다. 이 화면은 원본 확인과 이전만 제공하며 일반 생성·편집·완료 전환 기능은 제공하지 않는다.

사용자는 쓰기 가능한 대상 미리 알림 목록을 고르고 이전 대상 및 완료 상태를 확인한 뒤 이전을 실행한다. 완료한 내부 일감도 선택해 이전할 수 있다. 제목, 메모, 날짜, 시간, 완료 상태를 보존한다. 날짜 없는 항목에 임의 날짜를 넣지 않는다. 가능한 경우 원래 완료 시각도 보존한다.

항목별로 성공, 실패, 원본 변경으로 보류된 결과를 표시한다. 성공 확인 후에도 내부 원본은 보관한다. 이 보관본은 오늘 화면이나 완료 집계에 참여하지 않는다. 이번 버전에는 보관본 영구 삭제 기능을 추가하지 않는다.

## 이전의 안정성

EventKit 쓰기와 SwiftData 저장을 하나의 트랜잭션으로 취급하지 않는다. 내부 일감 UUID를 바탕으로 안정적인 이전 키를 만들고, 새 미리 알림의 URL 필드에 앱 전용 이전 표식을 남긴다. 원래 내부 모델에는 URL 필드가 없으므로 기존 사용자 URL을 덮어쓰지 않는다. 사용자 메모에 시스템 표식을 섞지 않는다.

이전 전 대상 목록에서 같은 키의 항목을 찾는다. 이미 있으면 다시 만들지 않고 결과를 확인한다. EventKit 저장 직후 앱이 종료되어도 재시도 시 기존 항목을 찾을 수 있어야 한다. 접근 실패나 조회 실패를 항목 부재로 간주하지 않는다. 같은 키가 여러 개면 보류하고 중복을 안내한다.

로컬 이전 기록은 원본 UUID, 이전 시점의 원본 내용, 대상 목록, 대상 식별자, 처리 상태를 보관한다. EventKit 식별자는 해당 기기에서의 조회 보조값이며 기기 공통 식별자로 사용하지 않는다. 저장 성공 후 원본을 다시 읽어 실제 필드가 일치하는지 검증한 뒤 성공 처리한다.

이전 이후 구버전 앱 또는 지연된 동기화로 내부 원본이 바뀌면 보관본 변경으로 표시한다. 해당 변경을 미리 알림 원본에 자동 덮어쓰지 않는다. 이전 화면에서 차이를 확인할 수 있게 한다.

동일 데이터의 이전은 한 기기에서 실행하고 다른 기기에는 Apple의 동기화가 끝난 뒤 결과를 확인하도록 안내한다. EventKit에는 여러 기기 사이 생성 작업을 잠그는 기능이 없으므로 동시 이전의 완전한 중복 방지는 보장하지 않는다. 자동 시작 및 백그라운드 일괄 이전은 하지 않는다.

## 타임블록과 집중 모드

새 타임블록의 연결 선택에서는 내부 일감을 제거하고 루틴 연결을 유지한다. 기존 내부 일감 연결은 보존하되 이전 일감이라는 읽기 전용 참조로 표시한다. 블록의 시간과 제목 편집은 가능하고 연결 해제도 가능하다. 저장만으로 기존 연결을 조용히 지우지 않는다.

이번 범위에서는 미리 알림과 타임블록 사이의 새로운 영구 연결 모델을 만들지 않는다. 기존 블록 자체는 계속 사용할 수 있다. 미리 알림의 날짜·시간은 미리 알림 편집으로 변경한다.

내부 일감을 대상으로 새 집중 세션을 시작하는 경로를 제거한다. 기존 세션이 남아 있는 경우 보관된 제목을 보여주고 종료할 수 있지만 내부 일감 완료를 쓰지 않는다. 루틴 및 블록 집중은 유지한다. 미리 알림을 대상으로 하는 새 집중 기능은 이번 범위에 포함하지 않는다.

## 저장소와 호환성

TaskItem 스키마, 과거 동기화 이벤트 디코딩 및 내부 일감 참조 해석은 유지한다. 일반 UI에서는 내부 일감 생성, 편집, 완료 쓰기를 호출하지 않는다. 기존 동기화로 수신한 일감은 보관/이전 화면에서만 취급한다.

미리 알림 내용이나 완료 상태를 기존 iCloud Drive 일감 이벤트로 재발행하지 않는다. 연결 해제나 권한 상실은 미리 알림 원본과 내부 보관본을 삭제하지 않는다. 기존 작업 디렉터리의 다른 변경은 보존하고 이 작업과 관련된 파일만 수정한다.

## 검증 및 완료 기준

- 미연결, 권한 거부, 빈 목록, 읽기 전용 목록의 안내와 추가 동작을 확인한다.
- 상단 추가가 미리 알림을 만들며 내부 일감을 만들지 않는지 UI 테스트로 검증한다.
- 오늘의 목록과 집계에 내부 일감이 나타나지 않고 미리 알림 완료가 원본에 반영되는지 확인한다.
- 이전의 날짜 없음, 날짜만 있음, 시간 있음, 완료 상태 및 완료 시각 보존을 검증한다.
- 부분 실패, 저장 후 결과 기록 전 중단, 재시도, 조회 실패, 중복 표식, 외부 변경을 가짜 접근 계층으로 검증한다.
- 기존 저장소와 동기화 파일을 읽을 수 있고 원본 보관본이 남는지 검증한다.
- 기존 일감 연결 블록의 편집/연결 해제, 루틴 및 블록 집중 기능을 회귀 검증한다.
- 공유 모델 테스트와 iOS/macOS 빌드를 실행하고 관련 UI 테스트를 실행한다. 실제 Apple 계정 간 동기화 및 실기기 권한 검증은 자동 테스트 결과와 구분해 보고한다.
- README 및 변경 기록에 일원화, 기존 일감 이전, 타임블록 연결 범위를 반영한다.

## 검토 결과

내부 일감 화면만 숨기는 방식은 기존 데이터 접근과 타임블록 연결 의미를 잃으므로 채택하지 않는다. 저장 스키마를 즉시 삭제하는 방식은 기존 저장소 및 동기화 호환성을 해치므로 채택하지 않는다. 일반 기능은 제거하고 보관·이전용 호환 계층을 남기는 방식으로 진행한다.
