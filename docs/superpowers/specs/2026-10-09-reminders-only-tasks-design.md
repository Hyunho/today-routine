# 일감을 Apple 미리 알림으로 통일

작성일: 2026-10-09
상태: 기존 내부 일감 삭제 요청 반영 · 구현 전 설계 검토

## 목적과 범위

사용자는 앱 내부에서 별도로 일감을 관리하는 기능을 없애고 Apple 미리 알림 연동만 남기기로 했다. 루틴의 반복 규칙, 단계, 실행 기록과 타임블록은 앱에서 계속 관리한다. 일감의 제목, 메모, 날짜와 완료 상태는 Apple 미리 알림이 원본이다.

이번 전환은 내부 일감의 일반 사용 경로 제거, 기존 내부 일감 전체 삭제, 오늘 화면 집계와 연결 기능 정리를 포함한다. 사용자의 명시적 요청에 따라 완료 여부와 관계없이 기존 내부 일감을 삭제하며, 보관 화면이나 미리 알림으로의 이전 기능은 만들지 않는다. TaskItem 타입은 기존 저장소와 동기화 파일을 읽고 정리하는 호환 계층으로만 유지한다.

## 확인한 현재 구조

- PlanningView에는 미리 알림과 내부 일감 목록이 함께 있으며 상단 추가 버튼은 TaskDraft를 생성한다.
- TodayView는 내부 일감을 목록, 시간 배치, 완료/미완료 집계에 사용한다. 미리 알림은 선택 날짜 마감 항목으로 이미 따로 표시한다.
- FocusSessionView의 내부 일감 집중 완료는 SwiftData의 완료 상태를 변경한다.
- TimeBlock.linkedID는 UUID이며 내부 일감 또는 루틴을 가리킨다. EventKit 식별자는 문자열이므로 그대로 대체할 수 없다.
- 내부 일감은 StoreSyncBridge를 통해 기기 간 동기화된다. 미리 알림은 현재 별도 복사본을 동기화하지 않는다.
- 기존 삭제 처리에는 연결된 타임블록의 연결 해제와 동기화 삭제 이벤트를 활용할 수 있다. SyncReducer는 삭제 표식이 있는 UUID의 후속 수정을 무시한다.

## 사용자 화면

### 일감

탭 이름은 일감을 유지한다. 목록에는 선택한 Apple 미리 알림 목록의 항목만 표시한다. 상단 추가 버튼도 AppleReminderEditor를 연다. 대상 목록은 편집 화면에서 확인하고 선택할 수 있다.

연결하지 않았으면 연결 안내와 연결 버튼을 표시한다. 권한 거부, 선택 목록 없음, 쓰기 가능한 목록 없음은 서로 구분한다. 작성할 수 없는 상황에서 내부 일감으로 대체 저장하지 않는다. 기존 조회, 편집, 완료 전환, 새로고침 기능을 유지한다.

### 오늘

내부 일감을 목록, 시간 배치, 남은 개수와 완료 개수에서 제외한다. 해당 날짜 마감 미리 알림 표시와 원본 완료 전환은 유지한다. 날짜가 없는 미리 알림은 일감 탭에서 조회한다. 루틴과 캘린더 표시 기준은 변경하지 않는다.

### 기존 일감 삭제

업데이트 후 저장소를 열 때 기존 내부 일감을 모두 삭제한다. 완료한 일감도 포함한다. 별도의 보관본이나 이전 기록을 만들지 않으며 Apple 미리 알림에 복사하지 않는다. 이 채팅에서 삭제를 명시적으로 요청했으므로 개발 진행을 위해 삭제 승인을 다시 요청하지 않는다.

삭제와 연결 해제는 저장소 트랜잭션으로 처리하고 동기화 삭제 이벤트를 함께 기록한다. 실패하면 롤백하고 앱의 오류 표시로 알린다. 삭제되지 않은 데이터를 화면만 숨긴 채 삭제 완료로 보고하지 않는다. 다시 실행해도 결과가 같은 정리 동작으로 구현한다.

## 동기화와 삭제의 안정성

현재 로컬 저장소에 있는 내부 일감과 동기화 상태에만 존재하는 일감 ID 모두 삭제 대상으로 다룬다. 기존 동기화 초기화 및 최초 이벤트 생성 순서를 확인하여 삭제 이전 상태가 누락되지 않도록 한다. 일감 삭제와 블록 연결 해제를 동기화 변경으로 기록해 다른 기기로 전달한다.

오프라인에서는 삭제 이벤트를 기존 영속 전송 대기열에 남기고 연결 복구 후 발행한다. 오래된 이벤트의 재수신으로 삭제된 일감이 복원되지 않아야 한다. 구버전 기기가 새로운 UUID의 내부 일감을 보내는 경우에도 새 버전은 해당 일감을 정리하고 삭제 이벤트를 발행한다. 수신한 과거 task 연결 블록도 연결을 해제한다. 변경이 없으면 이벤트를 추가 발행하지 않아 동기화 반복을 피한다.

일감 생성·수정·완료를 제공하는 구버전 앱은 더 이상 이 기능의 지원 대상이 아니다. 기기 간 일관된 동작을 위해 모든 기기의 앱을 업데이트하도록 변경 안내에 명시한다.

삭제 범위는 앱의 내부 일감 레코드와 활성 동기화 상태이다. 기존 동기화 이력 파일과 사용자가 별도로 만든 백업 파일을 지우거나 다시 쓰는 작업은 포함하지 않는다. 이력 안의 과거 내용은 삭제 표식으로 비활성화하며 앱에서 일감으로 복원하지 않는다.

## 타임블록과 집중 모드

새 타임블록의 연결 선택에서는 내부 일감을 제거하고 루틴 연결을 유지한다. 기존 내부 일감 연결은 일감 삭제와 함께 해제한다. 타임블록 자체의 제목, 날짜, 시작·종료 시각은 보존한다. 루틴 연결은 유지한다.

이번 범위에서는 미리 알림과 타임블록 사이의 새로운 영구 연결 모델을 만들지 않는다. 기존 블록 자체는 계속 사용할 수 있다. 미리 알림의 날짜·시간은 미리 알림 편집으로 변경한다.

내부 일감을 대상으로 새 집중 세션을 시작하는 경로를 제거한다. 내부 일감을 대상으로 한 기존 세션이 남아 있다면 종료 처리하고 삭제된 일감의 완료 상태를 쓰지 않는다. 루틴 및 블록 집중은 유지한다. 미리 알림을 대상으로 하는 새 집중 기능은 이번 범위에 포함하지 않는다.

## 저장소와 호환성

TaskItem 스키마와 과거 동기화 이벤트 디코딩은 삭제 호환성에 필요한 범위에서 유지한다. 일반 UI에서는 내부 일감 생성, 편집, 완료 쓰기를 호출하지 않는다. 삭제 정리는 저장소 초기화와 동기화 반영 경로 모두에 적용하고 화면 표시 전에 마친다.

미리 알림 내용이나 완료 상태를 기존 iCloud Drive 일감 이벤트로 재발행하지 않는다. 내부 일감 삭제는 EventKit 삭제 API를 호출하지 않는다. 미리 알림 연결 해제나 권한 상실도 Apple 미리 알림 원본을 삭제하지 않는다. 기존 작업 디렉터리의 다른 변경은 보존하고 이 작업과 관련된 파일만 수정한다.

## 검증 및 완료 기준

- 미연결, 권한 거부, 빈 목록, 읽기 전용 목록의 안내와 추가 동작을 확인한다.
- 상단 추가가 미리 알림을 만들며 내부 일감을 만들지 않는지 UI 테스트로 검증한다.
- 오늘의 목록과 집계에 내부 일감이 나타나지 않고 미리 알림 완료가 원본에 반영되는지 확인한다.
- 기존 저장소를 열면 완료/미완료 내부 일감이 모두 삭제되고 재실행해도 일감이 생성되지 않는지 검증한다.
- 삭제 실패 롤백, 오프라인 삭제 이벤트 보존, 과거 이벤트 재수신, 구버전의 새 일감 수신, 반복 동기화 시 이벤트 증가 방지를 검증한다.
- 동기화 상태에만 있던 일감도 삭제되며 기기 간 삭제와 연결 해제가 전달되는지 검증한다.
- 기존 일감 연결 블록의 제목과 시간이 보존되고 연결만 해제되는지 검증한다. 루틴 연결 및 루틴/블록 집중 기능은 회귀 검증한다.
- 내부 일감 정리 과정에서 Apple 미리 알림에 생성·수정·삭제 요청이 발생하지 않는지 검증한다.
- 공유 모델 테스트와 iOS/macOS 빌드를 실행하고 관련 UI 테스트를 실행한다. 실제 Apple 계정 간 동기화 및 실기기 권한 검증은 자동 테스트 결과와 구분해 보고한다.
- README 및 변경 기록에 일원화, 기존 내부 일감 삭제, 타임블록 연결 해제와 기기 업데이트 안내를 반영한다.

## 검토 결과

사용자 요청에 따라 기존 내부 일감을 삭제하며 보관·이전 기능은 제외한다. 데이터 레코드 삭제와 저장 스키마 타입 제거는 구분한다. 호환 타입과 과거 이벤트 해석은 안전하게 삭제를 전파하는 데 필요한 범위에서만 유지한다. 타임블록은 삭제하지 않고 일감 연결만 해제한다.
