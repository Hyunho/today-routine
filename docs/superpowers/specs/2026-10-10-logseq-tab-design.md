# 오늘의 루틴 Mac — Logseq 탭 통합 설계

작성일: 2026-10-10
상태: 설계 검토 대기

## 목적과 승인된 방향

오늘의 루틴 Mac 앱 안에서 Logseq 노트를 열고 편집한다. 사용자는 별도 앱 실행이 아니라 새 탭 안에 편집 화면을 통합하고, 원본 소스를 이 저장소에 포함하는 방향에 동의했다.

성공 기준은 기존 저널·페이지·검색·Markdown 편집을 새 탭에서 사용할 수 있고, 탭 전환과 정상 종료 시 편집 내용을 잃지 않는 것이다. 기존 루틴 데이터와 노트 파일 저장 체계는 분리한다. iPhone 확장, 루틴과 노트 간 데이터 연결, 새 동기화 기능은 포함하지 않는다.

## 소스 포함과 빌드 경계

- `Packages/NativeLogseq`에 저장소 내부 Swift 패키지를 둔다. `NativeLogseqCore`, `NativeLogseqUI` 소스와 대응 테스트를 복사하고 두 라이브러리 제품을 노출한다. 원본 실행 타깃, 앱 아이콘, 빌드 산출물, 실제 노트 데이터는 복사하지 않는다.
- 원본은 `/Users/hyunho/Work/logseq`의 현재 작업 파일이다. 확인 당시 HEAD는 `3a44dae204b568d354a0098a6577cf9ece66b37e`이며 미커밋·미추적 구현이 많다. HEAD만 가져오면 기능이 빠지므로 구현 시 복사 시점의 파일 목록과 SHA-256을 provenance 문서에 남긴다. 원본의 라이선스 파일이 있으면 함께 보존한다.
- 원본 저장소를 수정하거나 절대 경로로 의존하지 않는다. 이후 원본 변경은 자동 반영하지 않는다. 통합에 필요한 변경은 복사본에 적용하고 기록한다.
- `scripts/generate-project.py`에서 저장소 상대 경로의 로컬 패키지를 등록하고 Mac 앱 타깃에만 `NativeLogseqUI`를 연결한다. 생성된 Xcode 프로젝트도 갱신한다. iOS 타깃과 기존 RoutineCore 테스트에는 macOS 전용 모듈을 연결하지 않는다.

## 화면과 세션

- Mac 하단 탭 순서는 오늘 / 일감 / 피드 / 캘린더 / Logseq / 전체로 한다. 아이콘은 `doc.text`, 선택 태그와 접근성 이름은 `Logseq`로 통일한다. 전체 화면의 바로 가기에도 추가한다.
- 기존 `RootView`의 `TabView`에 편집 화면을 연결한다. 비활성 화면을 투명하게 겹쳐 두는 방식은 사용하지 않는다. 활성 탭의 툴바만 표시한다.
- Mac 전용 호스트가 `AppState`와 `EditorSession`을 소유한다. 탭 전환이나 집중 화면 표시로 뷰가 다시 만들어져도 세션은 유지한다. 첫 Logseq 진입 때 저장된 작업 공간을 한 번 복원한다.
- 첫 실행은 기존 Logseq의 파일/그래프 선택 화면이다. 사용자가 Native Logseq 그래프 폴더 또는 개별 `.md` 파일을 선택한다. 독립 앱의 환경설정이나 노트 경로를 자동으로 가져오지 않는다. 다음 실행부터 이 앱에서 마지막으로 열었던 항목을 복원하며, 실패하면 오류와 다시 선택할 수 있는 화면을 제공한다.
- 저널 모아보기, 날짜별 저널, 페이지 링크·백링크, 검색, 블록 편집, 실행 취소, 글자 크기, 원문 보기와 기존 충돌 UI를 재사용한다. 일반 Logseq 그래프 전체 호환성을 새로 약속하지 않는다.
- 하단 경로 표시는 `Logseq → 저널 모아보기`, `Logseq → 페이지 제목`, `Logseq → 파일명`처럼 현재 위치를 나타낸다.
- 기본 루틴 창은 기존 360–480pt 폭을 유지한다. Logseq 진입 시 현재 화면의 사용 가능 영역 안에서 기본 1120pt, 최소 760pt 폭으로 확장하고 사용자가 더 넓힐 수 있게 한다. 마지막 Logseq 창 크기와 일반 탭 창 크기를 따로 기억해 전환 시 복원한다. 집중 모드는 기존 좁은 창과 창 레벨 동작을 유지한다. 비활성 Logseq 뷰의 최소 폭이 다른 탭의 창 크기를 강제하지 않도록 한다.

## 저장·권한·종료

- 그래프의 기존 500ms 지연 자동 저장과 개별 Markdown의 명시적 저장 방식을 유지한다. 노트는 선택한 원본 경로에 저장하며 루틴 SwiftData/CSV 동기화에 넣지 않는다.
- Logseq에서 다른 탭 또는 집중 화면으로 이동하기 전에 한글 조합을 확정하고 저장을 완료한다. 저장 또는 조합 확정 실패 시 전환을 취소하고 편집 화면에 오류를 표시한다. 중복 전환 요청은 저장 중 비활성화한다. 모든 프로그램적 탭 변경도 같은 전환 경계를 거친다.
- `AppState`의 최근 경로 저장도 주입한 preferences를 사용하도록 일관되게 수정한다. 호스트는 Logseq 전용 키 이름 공간을 사용하고 UI 테스트는 별도 preferences와 임시 파일을 사용한다.
- 파일 선택 시 security-scoped bookmark를 보관하고 열려 있는 동안 접근 권한을 유지한다. 폴더/파일 교체 시 새 항목을 성공적으로 연 뒤 기존 접근 권한을 해제한다. 재실행 복원 시 stale bookmark를 갱신하며 접근할 수 없으면 재선택을 요청한다. 현재 로컬 비샌드박스 빌드도 계속 지원한다.
- 정상 앱 종료는 Mac 앱 delegate가 조합 확정과 저장을 기다린다. 다른 탭에 있더라도 열린 Logseq 세션을 검사한다. 저장 실패 시 원본의 재시도 / 사본 저장 후 종료 / 종료 취소 흐름을 재사용한다. 사본 저장 완료 전에는 종료하지 않는다.
- 창 닫기는 앱 전체 종료와 구분한다. 닫을 창의 편집 내용을 저장한 뒤 창을 닫고, 실패하면 창을 유지한다. 원본의 `windowShouldClose → NSApp.terminate` 정책을 그대로 복사하지 않는다. 중복 delegate 콜백과 비동기 저장 재진입을 막는다.
- 여러 호스트 창이 열려도 공유 세션을 초기화하거나 두 번 복원하지 않는다. 명령은 현재 키 창과 활성 탭을 기준으로 처리하며, 세션을 쓰는 창들의 편집 버퍼를 확정한 뒤 저장한다.
- 기존 외부 변경 감지, 덮어쓰기 중단, 사본 내보내기와 명시적 다시 읽기를 유지한다. 독립 Native Logseq 앱과의 동시 저장에 새로운 원자성 보장을 추가하지 않는다.

## 명령과 인터페이스

- 패키지의 기존 `AppState`, `EditorSession`, `WorkspaceView`를 공개 진입점으로 유지한다. 호스트는 생성, 최초 복원, 화면 활성화, 저장, 종료를 연결한다.
- 복사한 `WorkspaceCommands`에 활성 상태를 전달할 수 있게 하고 Logseq가 활성인 키 창에서만 명령과 단축키를 제공한다. 비활성 탭에서 기존 앱 메뉴와 표준 실행 취소/다시 실행을 가로채지 않는다.
- `Cmd+O`, `Cmd+Shift+O`, `Cmd+S`, `Cmd+N`, `Cmd+J`, `Cmd+F`, 확대/축소, 원문 보기와 블록 명령을 유지한다. 검색·원문 모달·저장 작업 중의 기존 명령 제한도 유지한다.
- 탭을 떠날 때 편집기 포커스를 정리해 숨겨진 텍스트 뷰가 키 입력을 받지 않게 한다. 돌아오면 열었던 문서와 선택 상태를 복원한다.
- Finder 파일 연결이나 기본 Markdown 앱 등록은 이번 통합에서 추가하지 않는다. 파일 열기는 탭과 앱 메뉴에서 제공한다.

## 검증과 전달

- 포함한 패키지의 코어·편집기 테스트와 기존 RoutineCore 테스트를 실행한다. Mac 앱을 빌드하고 iOS 시뮬레이터 빌드로 플랫폼 경계가 유지되는지 확인한다.
- 새 통합 테스트는 임시 그래프와 Markdown 파일로 열기 → 편집 → 탭 이동 → 복귀 → 재실행 복원을 검증한다. 실제 사용자 노트나 기본 preferences를 사용하지 않는다.
- 저장 실패/외부 변경 시 탭 전환 취소와 내용 보존, 정상 종료 저장, 실패 시 종료 취소, 창 닫기, 저장 중 중복 요청을 검증한다. 한글 조합 입력 도중 전환도 수동 확인한다.
- Mac UI에서 저널/검색/페이지 편집, 단축키 활성 범위, 탭별 툴바, 창 크기 복원, 집중 화면 왕복을 확인한다. 기존 피드·전체 화면의 독립 툴바 회귀 테스트를 포함한다.
- 샌드박스 빌드에서 선택한 파일/폴더의 재실행 접근 복원을 확인한다. 해당 환경에서 검증할 수 없으면 로컬 비샌드박스 검증과 구분해 제한을 기록한다.
- 기존 로컬 서명 빌드 스크립트로 실행 가능한 앱을 만들고 README와 검증 기록을 갱신한다. 기존 앱을 교체하거나 재시작해야 한다면 정상 종료 저장 경로를 거치며 강제 종료하지 않는다.
- 현재 저장소에 이미 있는 다수의 변경은 보존한다. 설계 문서와 구현 변경만 선택적으로 관리하며 기존 변경을 되돌리지 않는다.
