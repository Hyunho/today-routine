# 오늘의 루틴 — iCloud Drive 자동 동기화 설계

상태: 2026-10-02 사용자 설계 승인 — 루틴별 CSV, 날짜 행과 세부작업별 완료 여부 열. CSV 직접 수정도 앱에 자동 반영. 구현 계획 작성 단계이며 제품 코드는 아직 변경하지 않음.

## 사용자 의도

혼자 사용하는 오늘의 루틴 앱을 아이폰과 맥에서 사용하며, 수동 내보내기·가져오기 없이 기록이 자동으로 맞춰지기를 원한다. 앞선 대화의 CSV + JSON 조합과 iCloud Drive 폴더 사용을 기준으로 한다. 최초의 기기 저장 전용 요구는 기기 저장을 유지하면서 동기화를 추가하는 것으로 확장한다. 웹사이트와의 연결은 이번 범위에 포함하지 않는다.

## 공통 설계

- 각 기기는 기존 SwiftData 로컬 저장소로 동작한다. 실행 중인 SQLite 파일은 Drive에 놓지 않는다.
- 동일 Apple 계정의 iCloud Drive에서 사용자가 선택한 동일한 전용 폴더를 양쪽 앱에 연결한다. 최초 연결과 권한 재연결은 사용자 조작이 필요하다.
- JSON 변경 파일을 자동으로 주고받는다. 파일마다 고유 ID가 있고, 이미 게시한 변경 파일은 덮어쓰지 않는다.
- CSV는 사람이 표로 볼 수 있는 표현을 제공한다. JSON과 독립된 두 번째 원본으로 취급하지 않는다.
- 클라우드 전송 완료와 다른 기기 적용 완료는 다르다. 폴더 쓰기 성공을 양쪽 동기화 완료로 표시하지 않는다.
- 현재 프로젝트는 iOS 앱 실행 대상만 있다. 맥용 실행 대상과 네이티브 화면 조정도 연동 작업에 포함해야 실제 두 앱으로 검증할 수 있다.

## 실행 시점과 화면

로컬 변경 저장 직후 전송 대기열에 넣고, 앱 실행·활성화·공유 폴더 변경 감지 때 수신한다. 앱이 활성 상태인 동안 제한된 간격으로 누락 여부를 다시 확인한다. 오프라인에서도 로컬 편집이 가능하고, 다시 접근 가능해지면 미전송 변경을 재시도한다.

iCloud의 전달 시간이나 iOS가 앱을 정지한 동안의 즉시 반영은 보장하지 않는다. 다시 앱을 열면 수신과 병합을 재개한다. 백그라운드 실행 권한이 상시 실행을 보장하는 것처럼 안내하지 않는다.

설정에는 연결 폴더, 마지막 수신 확인 시각, 전송 대기 건수, 상대 기기의 마지막 적용 확인, 오류 및 다시 연결 버튼을 제공한다. 평상시 동기화 버튼을 누를 필요가 없도록 한다. 상대 기기가 꺼져 있으면 상대 확인을 기다리는 상태를 구별한다.

## 저장과 변경 기록

앱 데이터 변경과 로컬 변경 로그 저장을 하나의 SwiftData 트랜잭션으로 처리한다. 저장 오류가 나면 둘 다 롤백한다. 파일 전송 실패는 이미 저장된 로컬 데이터를 되돌리지 않고 대기열에 남긴다. 수신 변경 적용과 처리한 이벤트 ID 기록 역시 한 트랜잭션으로 처리한다.

공유 폴더는 동기화 공간 UUID와 형식 버전을 갖는다. 이벤트에는 형식 버전, 공간 ID, 이벤트 ID, 기기 ID, 논리 순번, 진단용 작성 시각, 변경 내용이 들어간다. 실제 시계 시각만으로 충돌 우선순위를 정하지 않는다.

각 기기는 수신한 논리 순번의 최댓값보다 큰 순번으로 다음 변경을 만든다. 동일 순번은 기기 ID와 이벤트 ID로 안정적으로 정렬한다. 이 순서는 동시 수정 시 모든 기기가 같은 상태에 도달하도록 하는 규칙이며 실제 사람이 마지막에 누른 시각을 증명하지 않는다.

서로 다른 속성 변경은 각각 유지한다. 같은 속성의 동시 변경은 위 순서의 마지막 값을 적용하며 다른 값도 원래 이벤트 파일과 충돌 이력에 남긴다. 루틴 이름과 메모는 개별 속성, 반복 방식·요일·목표는 일관성을 위해 하나의 묶음, 블록 시작·종료는 하나의 묶음으로 변경한다.

완료 기록은 루틴 UUID + 한국 날짜 키를 식별자로 사용한다. 단계 체크·해제, 전체 완료·취소·건너뜀은 명시적 작업으로 기록하고 동일한 순서로 적용해 하루 최대 한 번만 집계한다. 늦게 도착한 이벤트도 정렬된 변경 이력에서 영향을 받는 항목을 다시 계산한다.

삭제는 삭제 표시 이벤트로 전달한다. 일반 수정 이벤트만으로 삭제된 항목을 되살리지 않는다. 첫 버전은 삭제된 일감·블록의 동기화 복원 기능을 제공하지 않는다. 그룹 삭제는 루틴을 삭제하지 않고 연결만 해제한다. 현재 보관·복원 동작은 별도의 상태 변경이다.

알림 사용 여부와 권한은 각 기기에 남긴다. 동기화로 다른 기기의 알림을 켜지 않는다. 수신한 일정·완료 상태를 반영한 뒤 해당 기기의 알림을 다시 계산한다.

## 파일 접근과 실패 복구

공유 폴더 접근은 플랫폼의 사용자 선택 파일 권한과 파일 조정 API를 사용한다. iOS에서는 URL 문자열을 저장하는 것만으로 재실행 후 접근 가능하다고 가정하지 않고, 권한 복원 실패 시 재선택을 요청한다. macOS에서는 사용자 선택 폴더에 대한 샌드박스 권한을 적용한다.

이벤트는 작성 완료 후 노출하며 길이·필수 필드·형식 버전·공간 ID·내용 무결성을 검증한다. 아직 내려받지 못한 파일은 기다리고, 불완전·손상 파일은 적용하지 않는다. 알 수 없는 새 형식은 업데이트가 필요함을 알리고 해당 공간의 동기화를 중단한다. 로컬 기록은 그대로 사용한다.

동일 이벤트 ID에 내용이 다르면 오류로 격리한다. Drive의 충돌 버전도 검사하며 임의로 하나를 삭제하지 않는다. 첫 버전은 이벤트 파일 자동 정리·압축을 하지 않는다. 로그가 계속 늘어난다는 제한을 안내한다.

기존 기록은 최초 연결 전 로컬 백업을 만들고, 기존 UUID를 유지한 초기 이벤트로 전환한다. 빈 기기가 다른 기기의 기록을 지우지 않는다. 폴더에 별도의 기존 데이터가 있으면 UUID를 기준으로 합치며 이름이 같다는 이유만으로 서로 다른 루틴을 합치지 않는다. 폴더 연결 해제 시 로컬 기록과 공유 파일은 삭제하지 않는다.

## CSV 직접 편집의 자동 반영

사용자는 CSV를 엑셀·Numbers에서 직접 수정하고 저장한 내용도 앱에 자동 반영하도록 선택했다. 수동 가져오기 버튼은 정상 흐름에 필요하지 않다. Numbers 문서로 저장한 내용은 CSV 변경이 아니므로 CSV 형식으로 저장해야 반영된다. 사용자가 폴더 밖으로 복사한 파일은 감시하지 않는다.

### 루틴별 CSV 형식

사용자 요청에 따라 이전의 테이블별 CSV 여섯 개 제안을 대체한다. 하나의 CSV는 하나의 루틴 실행 기록을 표현한다. 첫 열은 날짜(한국 기준 YYYY-MM-DD), 나머지 열은 해당 루틴의 세부작업 이름이며 각 셀은 완료 여부다. 한 행은 하루다.

예: 아침루틴.csv

```csv
날짜,물 마시기,스트레칭,독서
2026-10-01,TRUE,TRUE,FALSE
2026-10-02,TRUE,FALSE,FALSE
```

TRUE는 완료, FALSE는 미완료로 저장한다. 대소문자 차이는 허용하며 내보내기는 대문자로 통일한다. CSV 자체에는 체크박스 UI가 없으므로 Numbers 등의 표시 설정은 별개다. 빈 셀은 미완료로 임의 변환하지 않고 해당 단계에 대한 변경 없음으로 취급한다. 과거에 존재하지 않았던 단계는 빈 셀로 표시하고, 당시의 이름 및 단계 식별 정보는 JSON 기준 스냅샷에 보존한다.

모든 해당 날짜의 유효 단계가 TRUE이면 전체 루틴 완료로 집계한다. 하나라도 FALSE이면 미완료다. 단계가 없는 루틴은 날짜,완료 두 열을 사용한다. 건너뜀은 boolean 값으로 손실 없이 표현할 수 없으므로 JSON에 보존하며 CSV를 단순 재저장하는 것만으로 해제하지 않는다. 건너뛴 날짜의 셀을 실제 변경하면 해당 체크 변경으로 건너뜀을 해제한다.

루틴 ID, 세부작업 ID와 표시 열의 대응, 기준 버전, 반복 일정·시간·그룹 등 설정은 CSV 옆 기준 JSON과 변경 이력에 둔다. CSV에는 사용자가 요청한 날짜와 세부작업 열만 표시하고 관리용 ID 열을 요구하지 않는다. 루틴 이름이 같더라도 루틴 ID별 폴더로 구분한다. 같은 루틴 안의 중복 단계 이름은 표시 열 이름에 구별용 번호를 붙이고 JSON에 정확한 대응을 기록한다.

CSV 편집 지원 범위는 완료 셀 변경과 날짜 행 추가다. 날짜 열로 기존 행을 식별하고 새 날짜도 루틴 ID + 날짜로 식별하므로 두 기기가 같은 행을 발견해도 중복 기록을 만들지 않는다. 동일 파일의 중복 날짜, 잘못된 날짜·boolean, 알 수 없는 열, 기준 JSON 부재는 오류로 보류한다. 열 순서는 이름과 JSON 대응으로 식별하되 열 이름 변경·새 단계 생성·루틴 설정 변경은 앱에서 수행한다. 기존 날짜 값을 다른 날짜로 바꾸면 이전 날짜 삭제로 추정하지 않고 새 날짜 행으로 취급한다.

CSV는 기준 스냅샷과 비교해 실제로 바뀐 셀만 반영한다. 오래된 CSV에 남아 있는 다른 셀의 값으로 최신 앱 상태를 덮어쓰지 않는다. 행 또는 열을 지운 것은 데이터·단계 삭제로 처리하지 않는다. 완료 취소는 해당 셀을 FALSE로 바꾸고, 기록·루틴·단계의 삭제·보관은 앱에서 명시적으로 수행한다. 일감·타임블록·그룹은 JSON으로 동기화하며 이번 CSV 편집 대상에는 포함하지 않는다.

CSV를 변경마다 자동으로 생성하되, 두 앱이 같은 CSV 경로를 덮어쓰지 않도록 기기별 출력 경로를 사용한다. 앱이 새 스냅샷을 내보낼 때에는 버전별 디렉터리에 CSV와 불변 기준 JSON을 함께 생성한다. 기존 CSV는 새 상태를 내보내는 과정에서 덮어쓰지 않는다. 각 기기의 최신 스냅샷 위치를 설정에서 열 수 있으며, 연결 폴더 안의 이전 버전 CSV를 편집한 경우에도 기준 버전과 비교해 변경을 감지한다. 이 방식은 파일 수가 늘고 최신 표의 경로가 바뀐다는 단점이 있지만, 엑셀에서 열어 놓은 편집본을 앱이 덮어쓰는 일을 피한다.

CSV의 원본 버전·정규화한 변경 내용에 기반해 중복 수신을 식별한다. 동일 편집본을 여러 기기가 관측해도 같은 변경을 두 번 집계하지 않는다. 이미 처리한 편집본에서 같은 내용을 반복 저장하는 것은 새 변경으로 취급하지 않는다. 과거 수정과 같은 내용을 다시 적용하려면 앱이 생성한 최신 기준 버전 CSV를 편집해야 하며, 오래된 기준의 편집과 현재 상태가 충돌하면 조용히 덮어쓰지 않고 충돌 안내를 보여준다. 충돌 없는 편집은 자동 처리하고, 같은 셀의 서로 다른 동시 편집만 사용자 선택 대상으로 남긴다.

공유 파일의 쓰기 중간 상태는 읽지 않도록 파일 조정과 안정화 확인을 사용한다. 파일 문법·데이터 검증이 실패하면 그 파일 전체를 보류하고 기존 기록을 유지한다. 파일명·행·오류 이유를 설정에서 표시한다. 참조 대상 파일이 늦게 도착한 경우는 영구 오류 대신 대기 상태로 두고 다시 검사한다.

CSV는 한글·쉼표·따옴표·줄바꿈을 안전하게 표현하고 UTF-8로 내보낸다. Numbers/Excel의 수식으로 해석될 수 있는 문자열은 내보내기에서 처리하고 앱이 생성한 이스케이프를 되돌리는 규칙을 문서화한다. 단계 식별 ID는 JSON에 문자열로 보관한다. CSV·JSON은 비밀번호 파일이 아니며 해당 폴더 접근 권한이 있는 사람은 내용을 읽을 수 있다.

## 맥 지원 범위

공유 모델·규칙·동기화 엔진을 재사용한다. macOS 14 이상 실행 대상을 추가하고 오늘·계획·루틴·기록 탐색, 편집 창, 키보드 조작, 설정·알림을 맥에서 검증한다. 메뉴 막대 앱, 위젯, App Store 배포는 제외한다.

## 검증 기준

1. 두 저장소에서 같은 이벤트 집합을 다른 순서로 받거나 중복 수신해도 같은 결과가 된다.
2. 오프라인 동시 편집, 같은 루틴의 완료·취소, 다른 단계 동시 체크, 삭제 후 늦은 수정, 시계 차이를 검증한다.
3. 저장 실패·전송 실패·수신 중 종료·재실행에도 로컬 변경과 미전송 로그가 유지된다.
4. 기존 저장소 업그레이드와 최초 연결·빈 기기 연결이 기존 기록을 지우지 않는다.
5. 손상·부분 다운로드·알 수 없는 형식은 기존 기록을 변경하지 않는다.
6. 기기별 알림 설정이 분리되고 동기화된 완료 기록에 따라 예약이 갱신된다.
7. 루틴별 CSV의 boolean 변경·날짜 행 추가·중복 날짜 거부·행/열 누락 시 기록 보존·단계 없는 루틴·과거 단계 변경, 파일별 원자적 적용, 한글·줄바꿈·따옴표, 수식 문자열, 잘못된 값, 외부 편집 중 앱 변경, 오래된 기준의 편집, 두 기기의 중복 감지, 수정→취소→재수정 흐름을 검증한다.
8. 아이폰 시뮬레이터와 맥 앱을 각각 빌드·실행하고, 두 임시 저장소 및 공유 테스트 폴더로 흐름을 자동 검증한다.
9. 실제 iCloud Drive와 아이폰·맥 간 전송은 서명·로그인·폴더 권한이 있는 환경에서 별도로 검증한다. 로컬 테스트 성공을 실제 iCloud 전달 성공으로 보고하지 않는다.

## 자체 검토

현재 로컬 저장을 유지하며 동기화 경계를 추가한다. 파일 쓰기 성공과 상대 기기 수신 완료를 구분하고, 중복·삭제·초기 데이터·앱 중단 시 복구를 명시했다. CSV 직접 편집 자동 반영을 포함하고, 사용자 요청대로 루틴별 날짜 × 세부작업 boolean 표로 변경했다. 설정·식별자·건너뜀 등 boolean 표로 표현할 수 없는 정보는 JSON에 보존한다. 앱이 CSV 편집본을 덮어쓰지 않도록 버전별 출력과 기준 JSON을 사용하며, 정상 편집은 자동 적용하고 충돌·오류만 예외로 안내한다. 동일 CSV 경로를 영구적으로 최신 상태로 유지하는 기능은 이 버전의 보장 범위에서 제외한다. 실제 iCloud 전달과 서명은 환경 검증 항목으로 분리했다.
