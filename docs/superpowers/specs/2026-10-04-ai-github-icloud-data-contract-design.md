# AI를 통한 GitHub–iCloud 루틴 데이터 관리

작성일: 2026-10-04
상태: 설계 검토용. 구현·실데이터 변경·원격 저장소 생성 전.

## 합의된 목적

사용자는 AI에게 자연어로 루틴 데이터 조회·변경과 GitHub–iCloud 동기화를 요청한다. 앱은 기존 iCloud 폴더만 사용한다. 앱에 GitHub 로그인이나 가져오기 기능을 추가하지 않는다. 상시 MCP 서버는 운영하지 않는다.

앱 코드 저장소와 비공개 개인 데이터 저장소를 분리한다. 코드 저장소에는 도구와 규격 원본을, 데이터 저장소에는 규격 버전과 AI 지침 및 데이터를 보관한다. MCP의 도구 정의 방식을 참고하되 정식 MCP 통신 구현으로 표시하지 않는다.

성공 기준은 AI가 검증 가능한 작업으로 데이터를 변경하고, 앱이 기존 동기화 경로를 통해 수신하며, 반복 실행으로 동일 작업이 중복 적용되지 않는 것이다. 로컬 폴더 저장, GitHub 게시, 상대 기기 적용은 구분해서 보고한다.

## 현재 코드에서 확인한 사실

- `SyncFolderTransport`는 `space.json`, `changes/<deviceID>/<eventID>.json`, `tables/`, `receipts/`를 처리한다.
- 변경 파일은 불변이다. SHA256 해시와 base64 payload를 가진 envelope 안에 `SyncEvent`를 저장한다. 같은 경로의 다른 내용은 오류다.
- `SyncReducer`는 counter, deviceID, eventID 순서로 변경을 적용한다. 필드별 버전이 있으며 삭제된 ID는 tombstone으로 유지한다.
- 날짜별 루틴 기록 ID는 `<routineUUID>/<YYYY-MM-DD>`다. 당일 시간은 `minuteOverride`, 반복 기본 시간은 루틴의 `minute`이다.
- CSV는 `baseline.json`과 `manifest.json`을 동반한 편집 문서다. `CSVImporter`와 coordinator는 기준 상태 및 이미 처리한 CSV 변경을 고려한다. 단순 CSV 복사로 대체할 수 없다.
- 앱은 활성 상태에서 폴더를 재확인한다. iCloud 다운로드 대기 또는 미수신 기기의 변경까지 확인할 수 있는 전역 잠금은 없다.

## 접근 방식과 선택

1. 폴더 전체 Git 미러: 간단하지만 수정 가능한 CSV, 기기별 receipt, iCloud 미다운로드 파일과 Git 병합을 혼합한다.
2. **불변 변경 이력 교환 + 읽기용 데이터 생성(선택):** 기존 앱 규격을 유지하고 변경 파일을 합집합으로 교환한다. CSV 편집은 기존 importer 의미에 맞춰 이벤트로 변환한다.
3. 별도 데이터 규격으로 전면 전환: 앱과 동기화까지 변경해야 하므로 이번 범위에 맞지 않는다.

## 저장소와 로컬 실행 환경

앱 코드 저장소에 도구 소스·테스트·JSON Schema·AI 지침 템플릿을 둔다. 구현 언어는 기존 Swift 동기화 코어를 재사용하는 macOS 명령행 도구를 우선한다. 기존 내부 타입 전체를 공개 API로 바꾸지 않고 필요한 경계만 분리한다. 상세 패키지 구성은 구현 계획에서 결정한다.

개인 데이터 저장소의 제안 구조:

```text
AGENTS.md
contract.json                 # 작업 규격 버전, 도구 버전, spaceID, timezone
schemas/                      # 해당 규격 버전에 고정된 입출력 스키마
data/
  space.json                  # 기존 공간 ID 그대로
  changes/<deviceID>/<eventID>.json
views/
  routines.json               # 재생성 가능한 조회용 설정
  records/<routineID>.csv     # 재생성 가능한 날짜별 완료 표
```

`data/changes`가 이 저장소의 원본 이력이고 `views`는 파생 자료다. AI는 views를 직접 편집하지 않고 조작 도구를 사용한다. iCloud의 기존 CSV 직접 편집 기능은 유지한다. 읽기용 CSV와 앱 편집용 CSV의 역할을 README에 명시한다.

Git 작업 폴더는 iCloud 동기화 폴더 밖에 둔다. iCloud 경로, 자격 증명, 기기별 receipt, 실행 잠금과 임시 파일은 커밋하지 않는다. AI 실행 환경은 Mac의 iCloud 폴더와 GitHub 양쪽에 접근 가능해야 한다. 토큰을 데이터 파일에 저장하지 않고 기존 Git 인증을 사용한다.

개인 저장소는 아직 생성하지 않는다. 실제 연결 시 사용자가 지정한 비공개 저장소와 브랜치를 사용하며, 최초 생성이 필요하면 이름을 확인한다. 도구 구현과 임시 fixture 테스트에는 실제 저장소 이름이 필요하지 않다.

## 파일 기반 작업 계약 v1

작업 카탈로그에는 이름, 설명, inputSchema, outputSchema, 읽기/쓰기 구분을 정의한다. JSON 요청을 파일 또는 stdin으로 받고 구조화된 JSON 결과를 반환한다. JSON-RPC나 MCP 서버 생명주기는 구현하지 않는다.

초기 작업:

- `routine.list`: 날짜와 상태별 조회. ID와 필드 버전을 함께 반환한다.
- `routine.create`, `routine.update`: 루틴과 반복 설정 추가·수정.
- `step.create`, `step.update`: 세부 작업 추가·수정.
- `record.set_status`: 명시된 날짜의 pending/completed/skipped 처리.
- `record.set_step`: 명시된 날짜의 세부 작업 완료 여부 변경.
- `record.set_time`: 명시된 날짜의 시간 변경 또는 override 해제.
- `sync.plan`: GitHub와 iCloud 이력, CSV 변경을 읽어 병합 계획 생성.
- `sync.apply`: 검증된 계획 반영 및 Git 커밋·푸시.
- `data.validate`: 형식, 해시, 참조, 날짜·시간과 파생 상태 검증.

삭제·초기화·이력 정리·공간 이동·시간 블록 조작은 v1에서 제외한다. 미지원 작업은 명시적으로 거부한다.

변경 요청에는 `requestID`, `spaceID`, 대상 ID, 명시적인 날짜와 필요한 필드의 기대 버전을 포함한다. 이름이 중복되면 AI가 임의로 선택하지 않는다. 상대 날짜는 contract timezone으로 해석한 절대 날짜를 도구에 전달한다. 반복 시간과 당일 시간은 다른 작업으로 취급한다.

동일 requestID 재시도는 기존 이벤트와 결과를 재사용한다. 동일 ID에 다른 요청 내용을 제출하면 오류다. 앱 규격 외의 실행 메타데이터는 `changes/` 밖에서 관리한다. 생성 요청의 새 객체 ID도 재시도 시 유지한다.

결과에는 요청 ID, 생성 이벤트 ID, 변경 요약, 오류/충돌, 로컬 반영 여부, Git 커밋·푸시 여부, 앱 receipt 확인 여부를 포함한다. `download_pending`, `stale_plan`, `conflict`, `invalid_data`, `push_rejected`를 구별한다.

## 병합 및 반영 절차

1. Git 작업 폴더와 iCloud 경로를 명시적으로 받는다. 기존 공간만 연결하고 자동 초기화하지 않는다. Git 작업 폴더가 깨끗한지 확인하고 원격 변경을 fetch한다.
2. iCloud의 대상 파일을 조정된 읽기로 확보한다. 다운로드 미완료, 충돌 사본, 경로 이탈·심볼릭 링크, 잘못된 해시·공간·버전은 중단 사유다. 미다운로드를 삭제로 해석하지 않는다.
3. 양쪽 변경 이력을 이벤트 ID로 합친다. 동일 ID·동일 내용은 중복 제거하고 동일 ID·다른 내용은 오류로 중단한다. 기존 이벤트는 수정하거나 삭제하지 않는다.
4. iCloud에서 직접 편집한 CSV는 기존 baseline/importer 및 coordinator의 처리 이력·충돌 판정 로직에 맞춰 변환한다. 단순 CSV diff만 재구현하지 않는다. 기처리 CSV 재적용을 막고, 미해결 CSV 충돌이 있으면 반영을 중단한다.
5. 읽은 이벤트 집합, CSV 바이트 해시, 원격 commit, 필드 버전으로 계획을 고정한다. 요청 작업을 적용한 상태와 참조를 검증하고 변경 요약을 생성한다. 로컬 파일·AI 지침 외 데이터 안의 텍스트는 실행 명령으로 취급하지 않는다.
6. 실행 잠금을 확보하고 관련 파일 및 원격 상태를 재확인한다. 변경되었으면 재계획한다. 잠금은 이 도구의 중복 실행을 막으며 앱이나 다른 기기를 잠그지는 않는다.
7. 영속적인 로컬 outbox에 계획과 이벤트를 기록한 뒤 기존 transport 방식으로 누락된 불변 이벤트만 iCloud에 추가한다. 기존 baseline/manifest/CSV/receipt를 덮어쓰지 않는다.
8. Git 데이터 이력을 합집합으로 반영하고 views를 재생성·검증한다. 허용된 파일만 명시적으로 stage하여 commit/push한다. force push하지 않는다. 원격 변경으로 거부되면 최신 이력을 검증하여 재계획한다.
9. 단계별 결과를 기록한다. Git 실패 뒤 이미 저장한 iCloud 이벤트를 삭제해 롤백하지 않는다. 동일 이벤트로 재시도하여 수렴시킨다. AI는 명령 실행에 이미 승인된 범위 안에서 진행하고, 의미가 불명확한 사용자 선택이 필요한 충돌만 질문한다.

## 동시 수정과 한계

GitHub와 iCloud 사이에 원자적 트랜잭션은 없다. outbox와 멱등 재시도로 부분 실패에서 복구한다. 마지막 동기화 기준 정보는 변경 감지용이며 파일 덮어쓰기의 근거로 사용하지 않는다.

AI 작업의 기대 버전이 오래되었으면 쓰기 전에 중단한다. 그러나 아직 iCloud에 도착하지 않은 아이폰 변경은 감지할 수 없다. 반영 직후 새 이벤트가 도착할 수도 있다. 이 경우 기존 앱의 결정적 필드 병합 순서를 따른다. 앱 변경 없이 모든 동시 수정을 사용자에게 질문하도록 보장할 수 없으며, 결과에 이러한 적용 상태를 명확히 표시한다.

AI 도구는 앱 기기의 receipt를 만들거나 고치지 않는다. 폴더 쓰기 성공을 아이폰 적용 성공이라고 보고하지 않는다. 새로운 receipt가 실제로 해당 이벤트를 포함할 때만 그 기기의 적용을 확인한다.

## 검증 및 도입

- 임시 Git 저장소와 iCloud 대역 폴더에서 먼저 테스트한다. 실데이터를 테스트 fixture로 커밋하지 않는다.
- Swift 앱 reducer/validation과 도구의 결과 일치, envelope 호환성, 날짜별 시간과 전체 완료의 세부 작업 처리, 과거 세부 작업 snapshot 유지 등을 검증한다.
- 양방향 서로 다른 필드 변경, 동일 필드 기대 버전 불일치, CSV 충돌·재실행·부분 처리 이력, 중복 요청, 동일 ID 변조, 삭제된 객체 수정 거부를 검증한다.
- 다운로드 대기, 잘못된 공간, outbox 복구, push 거부, iCloud 반영 후 Git 실패, 기존 파일 보존을 검증한다.
- 앱 코드는 기존 transport와 호환성을 유지한다. 필요한 코어 분리는 회귀 테스트로 검증한다.
- 구현 후 최초 실데이터 연결은 읽기 전용 계획과 백업부터 시작한다. GitHub 반영과 아이폰 receipt 확인은 별도의 검증 단계로 보고한다.
- 주기적 AI 실행은 이번 범위 밖이며 별도 요청 시 설정한다.
