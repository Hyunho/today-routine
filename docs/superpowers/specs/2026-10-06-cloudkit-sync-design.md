# 오늘의 루틴 CloudKit 전환 설계

상태: 전환 설계 초안. CloudKit 연결·업로드·기존 동기화 변경은 아직 수행하지 않음.

## 목표와 전제

사용자가 요청한 목표는 iCloud Drive 파일 교환 대신 CloudKit으로 기기 간 데이터를 동기화하는 것이다. 기존 루틴·기록·피드를 보존하고, 앱에서 변경한 데이터가 다른 기기에 빠르게 반영되도록 한다. 네트워크와 운영체제의 백그라운드 실행 정책에 따른 지연은 있을 수 있다.

현재 설치된 iPhone 프로필은 LocalProvision=true이며 CloudKit 권한이 없다. 이 프로필만으로 계정의 현재 가입 상태까지 확정할 수는 없다. 활성 Apple Developer Program 팀, iCloud 컨테이너, 기기별 서명 권한 확인이 실기기 전환의 선행 조건이다. 구매·가입은 자동으로 수행하지 않는다.

## 권장 구조

- 기존 SwiftData 저장소와 JSON 피드 저장소를 로컬 원본으로 유지한다. 오프라인 편집은 먼저 로컬에 확정한다.
- 전송은 CKSyncEngine과 사용자 개인 CloudKit 데이터베이스를 사용한다. iPhone과 Mac은 동일한 컨테이너·환경을 사용한다.
- 루틴에는 기존 SyncEvent·SyncReducer의 병합 규칙을 재사용한다. CloudKit 전송 계층은 로컬 저장과 분리한다.
- CKSyncEngine 상태, 전송 대기 변경, 서버 확인 여부를 영속 저장한다. 파일 동기화의 published 플래그를 CloudKit 업로드 완료로 취급하지 않는다.
- 앱 진입·로컬 편집 시 동기화를 요청하고, 원격 알림과 엔진의 재시도를 처리한다. 전송 성공을 받기 전에는 대기 변경을 삭제하지 않는다.
- 계정 변경 시 기존 전송을 중지한다. 이전 계정의 데이터를 새 계정으로 자동 업로드하지 않고 별도 로컬 보관 및 명시적 전환 절차를 제공한다.

SwiftData의 자동 CloudKit 연동으로 저장소를 통째로 교체하는 안은 채택하지 않는다. 현재 모델의 unique 제약, 기존 변경 기록 기반 충돌 처리, 별도 피드 저장소를 함께 다뤄야 하므로 전송 계층을 추가하는 편이 데이터 보존을 검증하기 쉽다.

## 동기화 범위

1. 루틴, 하위 단계, 그룹, 날짜별 완료·건너뛰기·시간 변경 기록.
2. 앱 자체 일감과 시간 블록.
3. 피드 구독, 읽음·읽지 않음, 나중에 읽기, 필터별 읽던 위치.
4. 나중에 읽기에 저장한 글은 본문과 출처도 보관하여 원본 피드에서 사라져도 복구 가능하게 한다. 일반 글은 원본 피드에서 가져온다.

Apple 미리 알림 원본은 EventKit이 담당하므로 CloudKit으로 재복제하지 않는다. 알림 권한·기본 알림·기기별 예외, 미리 알림 목록 선택, 진행 중 집중 타이머는 현재 기기별 동작을 유지한다. 피드의 루틴 알림 기록은 우선 기기별 기록으로 유지한다. 이 범위는 구현 전에 사용자 의도와 대조한다.

## 식별자와 충돌

- 루틴·일감은 기존 UUID, 이벤트는 기존 이벤트 ID를 보존한다. 같은 이벤트 재수신은 중복 적용하지 않는다.
- 루틴 연결 공간(spaceID)을 CloudKit 계정 메타데이터에 저장한다. 기존 공간이 다른 기기는 조용히 합치지 않고 가져오기 미리보기로 분리한다.
- 피드 구독은 정규화한 URL의 안정적인 해시로 식별한다. 현재 기기별 구독 UUID와 글 ID는 별칭 테이블로 변환한다. 글 ID는 구독 식별자와 기존 entry.identity로 만든다.
- 동일 URL의 구독을 여러 기기에서 동시에 추가해도 하나로 모은다. 구독 삭제는 tombstone으로 전달하여 오프라인 기기에서 되살아나지 않게 한다.
- 읽음과 저장 여부는 필드별 변경 순서를 갖는다. 서로 다른 필드의 동시 편집은 둘 다 보존한다. 같은 필드는 결정적인 순서로 수렴시킨다.
- 읽던 위치는 의도적인 스크롤 변경만 전송한다. 수신으로 이동한 위치를 다시 새 로컬 변경으로 전송하지 않는다. 아직 수신하지 않은 글의 위치도 즉시 폐기하지 않는다.
- 저장한 본문은 크기 제한과 자산 분리를 적용한다. 일반 피드 캐시의 정리는 사용자 삭제로 전파하지 않는다.

## 최초 전환과 복구

1. 로컬 저장소·피드·기존 폴더 설정을 백업한다. SwiftData가 열린 상태의 SQLite 파일 단순 복사는 사용하지 않는다.
2. iCloud 로그인, 컨테이너 접근, 팀·환경 일치를 검증한다.
3. 전환 중 편집은 로컬에 계속 저장하되, 폴더 수신·CloudKit 적용이 동시에 같은 데이터를 쓰지 않도록 전환 잠금을 둔다.
4. 서버 공간을 먼저 확인하고 기존 로컬 이벤트와 피드 ID를 연결한다. 서버 데이터와 로컬 데이터 양쪽을 고려해 첫 기기/추가 기기 전환을 구분한다.
5. 서버 업로드와 재조회 검증 후 CloudKit을 활성 전송 방식으로 확정한다. 중간 종료 시 체크포인트에서 재개하며, 실패해도 기존 로컬 데이터와 전송 대기 기록을 보존한다.
6. CSV 내보내기는 유지한다. 기존 iCloud Drive 폴더 파일을 삭제하지 않으며 CloudKit과 폴더 동기화를 동시에 자동 실행하지 않는다.

## 설정 화면

동기화 연결 상태, iCloud 로그인 필요, 마지막 성공 시각, 전송 대기 수, 오류·재시도, 수동 동기화를 표시한다. 정상 동기화 확인 전에는 '동기화 완료'로 표시하지 않는다. CloudKit 연결 해제는 로컬·서버 데이터를 삭제하지 않는다.

## 서명·배포

- 컨테이너 이름 후보: iCloud.com.hyunho.TodayRoutine. 실제 소유 팀과 생성 가능 여부 확인 후 확정한다.
- iOS와 Mac의 iCloud 서비스·컨테이너 권한 및 플랫폼별 푸시 권한을 프로비저닝한다.
- 기존 Mac 로컬 빌드 스크립트는 CODE_SIGN_ENTITLEMENTS를 비우고 있으므로 CloudKit용 로컬 권한 파일을 별도로 전달하도록 수정해야 한다. 앱 데이터 경로를 바꾸는 샌드박스 전환과 혼합하지 않는다.
- 개발 환경에서 두 실기기로 검증하고, TestFlight/배포 환경의 스키마 승격을 별도 수행한다. Release 구성이라는 이유만으로 CloudKit Production 환경으로 판단하지 않는다.

## 검증 기준

- 같은 구독·이벤트의 중복 전송, 삭제 후 재접속, 동시 완료 체크, 다른 필드 동시 변경이 수렴한다.
- 앱 종료 후 대기 변경 및 엔진 상태가 복원된다. 실패한 업로드가 완료 처리되지 않는다.
- 읽음·저장 해제·구독 삭제·읽던 위치가 두 기기에서 일치한다.
- 시간표·완료 기록·저장한 글이 전환 전후 일치하고 CSV 내보내기가 유지된다.
- 계정 로그아웃/교체, 권한 거절, 네트워크 단절, 서버 부분 실패, 토큰 만료, 저장공간 부족에 데이터를 잃지 않는다.
- 실제 Mac+iPhone에서 전경 및 복귀 동작을 확인한다. 시뮬레이터 통과만으로 동기화 완료를 선언하지 않는다.
