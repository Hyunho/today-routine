# 아이폰 집중 중 앱 차단 설계

작성일: 2026-10-02
상태: 문서화만 진행. 구현·권한 추가·배포·기기 차단은 수행하지 않음.

## 확정된 요구사항

- 대상은 아이폰에서 다른 앱 사용을 제한하는 집중 기능이다.
- **기본 정책은 허용된 앱을 제외한 나머지 앱을 모두 차단하는 방식이다.**
- 사용자는 차단할 앱을 하나씩 고르는 대신, 집중 중에도 사용할 앱을 허용 목록에 넣는다.
- 현재 요청의 산출물은 이 문서이며, 구현 시작은 별도 요청 이후에 진행한다.
- 아래의 세부 흐름과 데이터 구조는 구현을 위한 제안이다. 사용자에게 승인받은 요구사항과 구분한다.

## 기본 동작 제안

1. 아이폰에서 스크린 타임 접근 권한을 요청한다. 본인 기기를 관리하는 individual 권한을 사용한다.
2. 시스템 앱 선택 화면에서 허용할 앱을 선택하고 저장한다.
3. ‘집중 시작’ 화면에서 허용 앱과 집중 종료 시각을 확인한다.
4. 시작하면 시스템이 제한할 수 있는 앱 전체에 차단 화면을 적용하고, 허용 목록의 앱은 제외한다.
5. 종료 시각 도달 또는 사용자의 ‘집중 종료’로 이 앱이 적용한 차단을 해제한다.

허용 목록이 비어 있으면 시스템이 제한할 수 있는 앱 전체를 차단하는 의미다. 시작 화면에 이를 명확히 표시한다. 루틴을 생성하거나 시간만 변경한 것으로 차단을 자동 시작하지 않는다.

오늘의 루틴 앱은 종료·복구 화면에 접근할 수 있어야 한다. Apple은 applicationCategories의 `.all` 정책에서 제어 앱 자체가 제외된다고 문서화한다. 시스템 필수 기능 등 모든 앱을 예외 없이 잠근다고 보장하지 않으며, 지원 범위는 대상 iOS 실기기에서 확인한다.

## 루틴·시간 블록과의 연결 제안

- ‘오늘’의 루틴 또는 시간 블록에서 ‘집중 시작’을 선택한다.
- 루틴에는 종료 시간이 없을 수 있으므로 집중 시간을 별도로 지정한다. 시간표 카드의 표시 높이를 실제 집중 시간으로 사용하지 않는다.
- 시간 블록은 종료 시각을 기본값으로 제안한다.
- 초기 버전은 한 번에 하나의 집중 세션만 허용해 겹친 차단 정책을 피한다.
- 완료·스킵은 기존 루틴 기록이다. 집중 종료와 루틴 완료를 동일한 상태로 취급하지 않는다.
- 진행 중인 세션과 연결된 루틴의 시간을 이동해도 활성 차단 종료 시각을 조용히 변경하지 않는다. 변경은 집중 세션 화면에서 명시적으로 처리한다.
- 반복 일정에 맞춘 자동 차단, 복수 세션 및 복잡한 예약 규칙은 후속 범위다.

## 화면 제안

설정에 ‘집중 앱 차단’을 추가한다.

- 권한 상태: 미허용 / 허용 / 해제됨
- 기본 정책: ‘허용 앱 외 모두 차단’
- 허용 앱 편집
- 진행 중인 집중: 시작·종료 시각, 남은 시간, 연결된 루틴
- 집중 종료

권한이 없거나 적용에 실패했으면 ‘차단 중’으로 표시하지 않는다. 일반 루틴 기록 기능은 계속 사용할 수 있다. 본인용 권한은 사용자가 철회할 수 있으므로 해제 불가능한 강제 잠금이라고 안내하지 않는다.

## Apple API와 권한

- FamilyControls: 본인 기기의 권한 요청과 FamilyActivityPicker를 통한 앱 선택.
- ManagedSettings: `shield.applicationCategories = .all(except: allowedApplicationTokens)`로 허용 목록 외 차단을 적용하는 방향.
- 허용 앱을 다시 차단하지 않도록 이 기능의 개별 앱 차단 목록과 카테고리 제한을 중복 적용하지 않는다. 다른 앱이나 시스템이 설정한 제한까지 해제할 수 있다고 보장하지 않는다.
- DeviceActivity 및 모니터 확장: 앱이 전면에 없어도 종료 시각의 해제를 처리하는 방향. 지원되는 최소 구간, 등록 한도, 재시동 후 동작을 실기기에서 검증한다. 앱 내부 타이머만으로 자동 해제를 구현하지 않는다.
- 앱과 확장의 상태 공유에는 App Group 사용을 검토한다. 필요한 각 타깃의 서명과 권한을 별도로 구성한다.
- 별도의 이름을 가진 ManagedSettingsStore를 사용하여 이 집중 기능이 소유한 제한만 관리한다.
- 웹사이트 차단은 별도 API와 정책이 필요하다. 허용 앱 외 차단이 브라우저 내부의 모든 웹 접근까지 제한한다는 뜻은 아니다. 초기 범위는 앱 차단이다.

현재 설치에 사용한 무료 Personal Team은 Family Controls 개발 권한을 지원하지 않는다. 실기기 구현·검증에는 Apple Developer Program 팀이 필요하다. TestFlight 또는 App Store 배포에는 Family Controls 배포 권한 신청이 필요하며, 관련 확장 타깃도 확인해야 한다. 이 문서화 작업에서는 가입·구매·권한 신청을 진행하지 않는다.

## 저장 및 동기화 제안

아이폰에 다음 정보를 저장한다.

- 허용 앱 선택의 불투명 토큰과 정책 버전
- 집중 세션 ID, 연결 루틴/블록 ID, 대상 날짜
- 시작·종료 시각, 세션 상태, 마지막 적용 결과

앱 선택 토큰은 일반 앱 이름이나 Bundle ID 목록으로 취급하지 않는다. 초기 버전에서는 허용 목록과 활성 차단 상태를 해당 아이폰에만 저장하고 기존 CSV·JSON 동기화에 포함하지 않는다. Mac에서 루틴이 바뀌었다고 아이폰의 앱 차단을 자동 시작하지 않는다. 기기 간 공유는 토큰의 적용 범위와 권한을 검증한 뒤 별도 설계한다.

## 종료·복구 및 실패 처리

- 집중 시작 전에 권한, 종료 시각, 허용 목록, 해제 예약 가능 여부를 검증한다.
- 해제 예약이 실패하면 차단을 시작하지 않는다.
- 종료 시 이 기능이 소유한 차단을 해제하고 예약과 세션 상태를 함께 정리한다.
- 앱 실행·복귀 시 저장된 세션, 현재 시각, 권한 상태를 비교한다. 만료된 세션의 차단이 남아 있으면 해제한다.
- 권한 철회, 기기 재시동, 확장 콜백 지연, 저장 실패에 대한 복구 경로를 제공한다.
- 허용 앱 변경은 활성 세션에 적용할지 명시하고, 실패하면 기존 정책을 유지하며 결과를 알린다.

## 구현 전·후 검증 기준

- 허용 앱은 열리고, 허용하지 않은 제한 가능한 앱에는 차단 화면이 표시된다.
- 허용 목록이 비어 있는 경우와 여러 앱이 있는 경우를 모두 확인한다.
- 제어 앱으로 돌아와 집중을 종료할 수 있다.
- 종료 시각 이후 앱이 전면에 없어도 해제되는지 실기기에서 확인한다.
- 수동 종료, 권한 철회, 재시동, 예약 실패 뒤 차단이 잘못 남지 않는다.
- 차단 상태와 루틴의 완료·스킵·당일 시간 변경이 서로 덮어쓰지 않는다.
- 인터넷이 없을 때도 이미 승인된 기기 내 세션의 적용·종료가 동작하는지 확인한다.
- 시뮬레이터 빌드만으로 실제 차단·해제 검증 완료를 선언하지 않는다.
