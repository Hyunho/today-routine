# 오늘의 루틴 수신함 설계

작성일: 2026-10-06
상태: 구현 전 사용자 검토

## 목적과 합의 범위

아이폰·맥의 오늘의 루틴 앱 안에 다섯 번째 탭 `수신함`을 추가한다. 루틴 알림과 구독한 뉴스·블로그의 새 글을 한곳에서 확인한다.

사용자가 요청한 기본 기능은 RSS 주소 등록·삭제, 최신 글 통합 타임라인, 피드 본문 표시와 원문 열기, 나중에 읽기 저장, 같은 기기에서 읽던 목록 위치 복원이다. 전체 / 루틴 알림 / 구독 글 필터와 읽음 표시도 포함한다.

첫 구독 주소:
`https://hyunho-feeds.pages.dev/99cf9e8a101b6d8561a2c2e9aebea93d/feed.xml`

조회 결과 RSS 2.0 형식, 제목 `통합 브리핑`, 글 13개였다. 이 개수와 글 내용은 구현의 고정값으로 사용하지 않는다.

## 구현 접근 선택

1. 별도 로컬 수신함 저장소와 기존 알림 예약 연동: 이번 설계의 선택. 기존 루틴 데이터와 동기화 형식을 변경하지 않고 수신함을 추가할 수 있다.
2. 기존 SwiftData 스키마 및 iCloud Drive 변경 이벤트 확장: 기기 간 수신함 동기화에 유리하지만 데이터 이행과 충돌 처리 범위가 커진다. 후속 기능으로 검토한다.
3. OS의 현재 전달된 알림 목록만 표시: 사용자가 OS에서 지우면 기록을 보존할 수 없고 RSS 저장도 별도로 필요하므로 채택하지 않는다.

## 화면과 동작

- 기존 오늘 / 일감 / 루틴 / 기록 뒤에 수신함 탭을 추가한다. 아이폰과 맥에서 동일한 기능을 제공한다.
- 상단에 전체 / 루틴 알림 / 구독 글 필터, 나중에 읽기 전환, 새로고침 및 구독 관리 버튼을 둔다.
- 각 행에 출처 종류, 제목, 출처 이름, 시각, 읽음 여부, 저장 여부를 표시한다. 정렬은 날짜 내림차순이며 같은 날짜는 항목 ID로 안정적으로 정렬한다.
- 항목을 열면 읽음으로 표시한다. 읽음 표시는 루틴 완료 상태에 영향을 주지 않는다.
- RSS 상세에는 제목, 출처, 발행 시각, 제공된 본문과 원문 열기·나중에 읽기 버튼을 표시한다. 본문이 없으면 안내와 원문 링크를 제공한다.
- 루틴 알림 상세에는 알림 생성 당시 제목과 예정 시각을 표시한다. 연결된 루틴의 현 상태를 확인하고 기존 루틴 편집 화면으로 이동할 수 있다. 루틴이 삭제되면 기록은 남기고 이동 버튼 대신 삭제 안내를 표시한다.
- 필터별 최상단 가시 항목 ID를 저장한다. 탭 재진입·앱 재실행 시 복원하며 항목이 없으면 목록 상단으로 이동한다. 새로고침 중에도 기존 가시 항목을 유지한다. 상세 본문의 픽셀 단위 위치 복원은 첫 버전에 포함하지 않는다.
- 빈 목록, 구독 없음, 갱신 중, 피드별 갱신 실패, 로컬 저장 실패를 구분해 표시한다.

## RSS 수집

- 사용자가 직접 입력한 HTTPS 피드 주소를 지원한다. 일반 웹페이지에서 피드를 자동 발견하는 기능은 후속 범위다. HTTP 주소는 HTTPS 주소 입력 안내를 표시한다.
- RSS 2.0과 Atom의 제목, 링크, 식별자, 발행·수정 날짜, description/summary/content 및 content:encoded를 해석한다. 날짜가 없거나 파싱되지 않으면 최초 수집 시각을 고정 사용한다.
- 식별자는 구독 ID와 피드의 guid/id를 우선 사용하고, 없으면 원문 URL, 마지막으로 제목·발행일 기반의 안정적인 해시를 사용한다. 반복 갱신으로 중복을 만들지 않는다.
- URLSession 요청에 제한 시간 20초, 응답 크기 5 MiB 한도를 적용한다. 다운로드 중 누적 크기를 확인하고 초과하면 취소한다. HTTP 실패, HTML 응답, 잘못된 XML을 구분한다. XML 외부 엔티티를 읽지 않는다.
- 본문은 네트워크 접근과 스크립트 실행이 없는 HTML→텍스트 변환을 거쳐 표시한다. 원문 링크는 http/https만 허용하고 시스템 브라우저에서 연다. 원문의 광고 제거·전체 본문 추출 및 이미지·영상 플레이어는 이번 범위에 없다.
- 최초 실행에 기본 구독을 한 번만 저장한다. 등록 플래그를 함께 보존해 사용자가 삭제한 기본 구독을 다시 생성하지 않는다. 기본 구독의 첫 다운로드가 실패해도 구독 자체와 재시도 수단은 남긴다.
- 수신함 진입 시 마지막 갱신으로부터 15분 이상 지났으면 갱신하고 수동 새로고침은 언제든 가능하다. 중복 갱신을 합치며 구독 삭제 중의 늦은 응답은 버린다.
- 개별 피드 실패는 다른 피드의 갱신을 막지 않고 기존 글을 유지한다. 앱이 닫힌 동안 주기적으로 수집하거나 RSS 새 글을 OS 알림으로 보내지는 않는다.
- 구독 삭제 시 해당 구독의 일반 글은 제거하고 나중에 읽기로 저장한 글은 출처 정보와 함께 유지한다. 삭제 확인창에 이 동작을 알린다.
- 피드별 일반 글은 최신 500개까지 유지하고 저장한 글은 보존한다.

## 루틴 알림 기록

현재 ReminderPlanner와 NotificationService는 루틴 알림만 지원한다. 일감 알림은 이번 기능으로 새로 만들지 않는다.

- 기존 ReminderPlanner가 계산한 예정 항목을 수신함 저장소의 대기 목록에도 기록한다. OS 권한과 무관하게 앱 안의 루틴 알림 기록으로 사용하며 OS 알림 예약 동작은 유지한다.
- 앱 활성화, 기존 알림 갱신, 수신함 진입 및 수신함이 활성인 동안 분 단위 확인 시, 대기 목록에서 예정 시각이 지난 항목을 기록으로 옮긴다.
- 안정적인 기존 알림 ID(`routine/<UUID>/<dayKey>`)를 사용해 같은 알림이 중복 생성되지 않게 한다. 제목·예정 시각·루틴 ID·날짜 키를 함께 저장한다.
- 예정 시각 이전의 완료·취소·알림 끄기·시간 변경·삭제는 새 계획과 대조해 대기 항목을 취소 또는 갱신한다. 이미 시각이 지난 항목은 먼저 기록으로 확정하고 이후 현재 일정 변경으로 지우지 않는다.
- 앱이 닫혀 있을 때 지난 알림은 다음 실행 시 기존 대기 목록으로 복구한다. 과거 일정은 현재 루틴 설정을 이용해 임의로 재생성하지 않는다. 설치 이전이나 미리 기록하지 않은 기간의 알림은 소급 생성하지 않는다.
- 이것은 예정 시각에 근거한 앱 내부 기록이다. 알림 상세에 `예정 시각 기준 기록`을 표시하며 OS 실제 전달 여부나 사용자의 확인 여부를 추측하지 않는다.
- 일반 루틴 알림은 최근 90일 보관하고 나중에 읽기로 저장한 항목은 유지한다.

## 구조와 저장

- `InboxTypes`: 구독, 글, 루틴 알림, 대기 알림, 읽음·저장 상태, 필터별 위치, 저장 형식 버전.
- `InboxStore`: Application Support의 독립 JSON 파일을 원자적으로 읽고 쓴다. 쓰기에 성공한 상태만 화면에 반영한다. 손상·지원하지 않는 버전은 원본을 보존하고 오류를 표시한다.
- `FeedParser`와 `FeedClient`: XML 해석과 네트워크 처리를 분리해 fixture 및 가짜 네트워크로 검증한다.
- `InboxModel`: MainActor에서 갱신·병합·저장·위치 복원·알림 기록을 조정한다. 장시간 네트워크·파싱으로 UI를 막지 않는다.
- `InboxView`, `FeedSubscriptionsView`, `InboxDetailView`: 기존 한국어·청록색 UI와 좁은 맥 창 크기에 맞춘다.
- AppModel 및 RootView는 수신함 모델 수명, 다섯 번째 탭, 앱 활성화·알림 계획 갱신 연결만 담당한다. 수신함 저장 오류가 기존 루틴 사용을 막지 않게 한다.
- UI 테스트용 루틴 저장 ID에 대응하는 독립 수신함 경로를 사용한다. 실제 사용자 데이터나 네트워크에 의존하지 않는다.
- 기존 SwiftData 스키마·루틴 iCloud Drive 포맷은 유지한다. 기기 간 수신함 동기화는 이번 범위에서 제외한다.
- 작업 디렉터리에 기존 미커밋 변경이 있다. 변경 파일을 되돌리지 않으며 필요한 통합 부분만 수정한다. 프로젝트 재생성 전후 차이를 확인한다.

## 검증과 완료 조건

- RSS/Atom 및 네임스페이스 본문, 날짜 오류, 빈 본문, 부적절한 링크, 깨진 XML, 중복 식별자에 대한 parser 테스트.
- 중복 갱신, 구독 삭제 중 늦은 응답, 기본 구독 삭제 후 재실행, 저장 항목 보존, 기록 보관 한도 및 저장 실패 테스트.
- 루틴 알림 예정 시각 전후, 같은 알림 반복 확인, 시간 변경·완료·취소, 앱 재시작 후 대기 기록 반영 테스트.
- 필터별 위치 복원, 항목 삭제 후 복원, 읽음·나중에 읽기 상태의 재실행 보존 테스트.
- 아이폰·맥 UI 테스트로 수신함 탭 진입, fixture 구독 추가·삭제, 본문 열기·저장·필터를 확인한다.
- 기존 핵심 테스트와 아이폰·맥 빌드를 실행한다. 지정 실제 피드로 수동 새로고침을 확인하되 자동 테스트 fixture에 개인 피드 본문을 복제하지 않는다.
- README에 수신함 사용법, 로컬 저장, 갱신 시점과 알림 기록의 의미를 명시한다.

## 검토 결과

사용자가 확정한 다섯 RSS 기능, 루틴 알림 통합과 첫 구독을 모두 반영했다. 루틴 알림을 실제 OS 전달 기록으로 오인하지 않도록 생성 기준을 명시했다. 동기화·일감 알림·백그라운드 수집·원문 추출은 현재 코드 및 첫 버전 범위와 분리했다. 미정 항목이나 외부 서비스 계정 의존성은 없다.
