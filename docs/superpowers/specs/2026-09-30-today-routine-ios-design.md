# 오늘의 루틴 — iPhone 앱 설계

작성일: 2026-09-30
상태: 대화에서 기능 범위 승인됨. 상세 설계 검토 대기.

## 1. 목적과 확정된 요구사항

기존 ‘오늘의 루틴’ 사이트의 주요 흐름을 아이폰에서 사용할 수 있는 독립 앱으로 만든다.
사용자는 루틴과 일감을 정리하고, 오늘의 실행 상태를 기록하며, 주간 진행 상황을 확인한다.
사용자 결정: 첫 버전의 데이터는 아이폰에만 저장한다. 사이트 동기화는 추후 검토한다.
대화에서 승인된 범위: 오늘, 루틴 관리, 일감과 타임블록, 주간 기록, 기기 알림.

사이트의 오늘·루틴·설정 화면을 읽기 전용으로 확인했다. 모든 세부 기능을 복제하는 요구사항은 아니다.

## 2. 구현 방식

SwiftUI 네이티브 앱과 SwiftData 로컬 저장소를 사용한다. 최소 지원 버전은 iOS 17로 제안한다.
CloudKit 동기화를 끄고 서버 없이 작동한다. 외부 라이브러리는 첫 버전에 사용하지 않는다.
웹 화면을 앱에 넣는 방식은 기존 서버 의존성을 남기므로 이번 독립 저장 요구에 적합하지 않다.
다른 모바일 플랫폼과 코드를 공유하는 방식은 가능하지만 현재 목표가 아이폰이므로 별도 도입하지 않는다.

화면은 저장소를 직접 수정하지 않고 기능별 서비스에서 저장과 실행 규칙을 처리한다.
모델은 UUID 식별자와 생성·수정 시각을 가진다. 추후 동기화를 고려해 저장 계층을 분리하되 동기화 코드는 만들지 않는다.

## 3. 화면과 사용자 동작

하단 탭은 오늘 / 계획 / 루틴 / 기록으로 구성한다. 설정은 화면 상단에서 연다.
한국어를 기본으로 하며 시스템 글자 크기와 밝은·어두운 화면에 대응한다.

### 오늘

선택한 날짜의 반복 루틴과 예정 일감을 시간순으로 보여준다. 시간이 없는 항목은 별도 구역에 표시한다.
남은 항목과 완료 항목 수를 표시하며 완료, 건너뛰기, 되돌리기를 제공한다.
하위 단계가 있는 루틴은 펼쳐서 체크할 수 있다. 전체 완료는 모든 단계를 완료 처리한다.
마지막 단계 완료 시 루틴도 완료된다. 단계 체크를 해제하면 루틴은 다시 미완료가 된다.
주간 횟수 목표 루틴은 별도 구역에서 오늘 실행할 수 있다. 같은 루틴은 하루 최대 1회로 집계한다.

### 계획

일감 목록과 하루 타임블록을 전환한다.
일감은 제목, 메모, 선택 날짜·시간을 가지며 추가·수정·완료·삭제할 수 있다.
타임블록은 날짜, 시작·종료 시간, 제목, 선택한 일감 또는 루틴 연결을 가진다.
종료 시각은 시작 이후여야 한다. 첫 버전은 하루 안에서 끝나는 블록을 지원한다.
겹친 블록은 경고를 보여주되 저장할 수 있다. 연결은 일정 표시용이며 완료 상태를 자동 변경하지 않는다.

### 루틴

루틴 이름, 메모, 그룹, 반복 방식, 실행 시간, 하위 단계를 편집한다.
반복 방식은 매일 / 요일 선택 / 주 N회 목표로 구분한다. 주간 목표는 1~7회다.
그룹 관리, 수동 순서 변경, 시간·그룹별 보기, 일시정지, 보관 및 복원을 지원한다.
보관한 루틴은 오늘 목록에서 제외하고 기존 기록은 유지한다.
그룹 삭제 시 해당 루틴의 그룹만 해제한다. 하위 단계는 한 단계 깊이까지만 지원한다.

### 기록

월요일부터 일요일까지의 주간 완료 현황과 루틴별 달성 횟수를 보여준다.
건너뛰기는 완료 횟수에 포함하지 않는다. 완료 취소는 기록과 집계에 즉시 반영한다.
첫 버전은 완료 횟수와 주간 목표 진행도를 제공하며 과거 일정 변경에 영향받는 달성률 계산은 제외한다.

### 설정과 알림

루틴별 알림 사용 여부와 시간을 설정한다. 운영체제 권한 요청은 사용자가 알림을 켤 때 진행한다.
UserNotifications로 기기 알림을 예약한다. 사용자 허용 시 앱이 닫혀 있어도 예약 알림을 받을 수 있게 구현한다.
매일·요일 반복 루틴은 예정 실행일의 알림을 예약한다. 주간 횟수 목표 루틴은 자동 시간을 추정하지 않는다.
다음 7일의 미래 알림 중 가까운 60개까지 예약해 시스템 대기 알림 한도에 여유를 둔다.
앱 활성화, 루틴 수정, 오늘 완료·건너뛰기 후 예약을 갱신한다. 완료·건너뛴 날짜의 알림은 취소한다.
권한 거부나 예약 실패는 상태를 표시하고 나머지 앱 기능은 계속 사용할 수 있다.
7일 이상 앱을 열지 않을 때의 알림 자동 연장은 보장하지 않으며 이 제한을 설정에서 안내한다.
저녁 미완료 요약, 서버 푸시 및 백그라운드 동기화는 후속 범위로 남긴다.

## 4. 데이터 모델과 날짜 규칙

- Routine: 이름, 메모, 반복 종류, 요일 목록, 주간 목표, 선택 실행 시간, 그룹 ID, 정렬 순서, 상태.
- RoutineStep: 루틴 ID, 이름, 순서.
- RoutineGroup: 이름, 순서.
- RoutineDayRecord: 루틴 ID와 날짜 키, 미완료·완료·건너뜀 상태, 완료한 단계 ID, 이름 스냅샷, 완료 시각.
- TaskItem: 제목, 메모, 예정 날짜·시간, 완료 시각.
- TimeBlock: 날짜, 시작·종료 분, 제목, 선택 연결 ID와 연결 종류.
- ReminderPreference: 루틴 ID, 사용 여부, 알림 시·분.

날짜 키와 주간 경계는 기존 사이트에 맞춰 Asia/Seoul 달력 기준으로 계산한다.
완료 시각 자체는 절대 시각으로 저장한다. 루틴과 날짜 쌍에는 실행 기록을 하나만 유지한다.
일정 수정은 오늘과 미래의 표시 규칙에 반영하고 이미 저장된 과거 실행 기록은 유지한다.
루틴 단계 편집 후에도 과거 완료 기록은 바꾸지 않는다. 오늘 단계 상태는 현재 유효한 단계 ID로 계산한다.
일감 삭제 시 연결 타임블록은 제목을 남기고 연결을 해제한다.

## 5. 첫 실행과 저장 안정성

기본 제안: 빈 상태에서 시작하고 루틴 추가를 안내한다. 사이트 데이터는 자동으로 복사하지 않는다.
저장소는 앱 전용 로컬 영역을 사용한다. 앱 자체에서 데이터 업로드나 iCloud 동기화를 하지 않는다.
운영체제의 기기 백업 여부는 사용자의 iPhone 설정에 따른다.
저장 오류는 화면에서 알리고 성공한 것처럼 표시하지 않는다. 입력 폼은 복구할 수 있도록 유지한다.
저장소를 열지 못하면 오류와 재시도 화면을 제공하며 기존 데이터를 자동 초기화하지 않는다.
보관을 기본으로 사용하며 일감·단계 삭제에는 확인을 제공한다.

## 6. 구성과 검증

앱 시작·탭 구성 / 데이터 모델·저장소 / 일정·기록 서비스 / 알림 서비스 / 기능별 화면으로 분리한다.
완료 기준:

1. 시뮬레이터용 Xcode 빌드와 앱 실행에 성공한다.
2. 루틴 생성 → 오늘 표시 → 단계 체크 → 완료 → 주간 집계가 연결된다.
3. 앱 종료 후 재실행해 루틴·일감·기록·타임블록이 유지된다.
4. 요일 반복, 주간 경계, 중복 완료 방지, 완료 취소, 보관 규칙을 단위 테스트한다.
5. 일감과 타임블록의 생성·편집 및 잘못된 시간 입력을 검증한다.
6. 알림 허용·거부 처리 및 예약·취소를 검증한다. 실제 기기의 알림 전달 여부는 별도 확인 결과로 보고한다.
7. 작은 아이폰 화면과 큰 글자 크기에서 핵심 조작이 가능한지 확인한다.

## 7. 이번 작업의 전달 범위

Xcode 프로젝트, 소스 코드, 테스트, 실행 방법을 전달하고 맥의 시뮬레이터에서 검증한다.
실제 아이폰 설치에는 기기 연결과 서명 설정이 필요하므로 가능한 환경을 확인한 후 진행한다.
App Store 및 TestFlight 배포, 웹사이트 변경, TickTick 연동, 로그인, 위젯, 실시간 활동은 첫 구현 범위에 포함하지 않는다.

## 8. 자체 검토

로컬 저장 요구와 서버 의존 기능의 범위가 일치한다. 기록·반복 규칙과 날짜 기준을 명시했다.
알림의 예약 기간과 운영체제 제약을 드러냈으며 실기기 검증을 시뮬레이터 검증과 구분했다.
초기 데이터, 최소 OS, 알림 세부 범위는 이 문서에서 제안한 결정이며 사용자 상세 설계 검토 대상이다.
