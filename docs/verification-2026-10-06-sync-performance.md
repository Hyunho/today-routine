# 동기화 성능 검증 — 2026-10-06

## 관찰과 수정

실제 Mac 앱 빌드 4는 실행 7분 시점에도 CPU 사용률이 약 99%였다. 프로세스 샘플에서 동기화 폴더 읽기·디코딩과 파일 쓰기 조정 대기를 확인했다. 시스템 로그에는 변경 없는 내보내기에도 반복되는 쓰기 조정 요청이 있었다. 실제 동기화 폴더에는 기준 문서 1,225개, 약 121MiB가 누적되어 있었다.

- 빈 이벤트 발행은 즉시 반환한다.
- 이미 내보낸 CSV 확인은 읽기 조정을 사용한다. 새 내보내기는 쓰기 조정 안에서 다시 확인한다.
- CSV 가져오기에서 현재 상태를 재사용하고, 이벤트가 추가되면 갱신한다.
- 내보내기 상태 해시는 묶음당 한 번 계산하고 문서 생성은 백그라운드에서 수행한다.
- 사용자 CSV 수정과 기존 동기화 파일 형식을 유지한다. 누적 파일을 삭제하지 않았다.

## 검증 결과

- 변경 없는 내보내기의 쓰기 조정 횟수 회귀 테스트: 수정 전 2회 증가하여 실패, 수정 후 증가 없이 통과. 사용자 CSV 내용도 보존.
- 묶음 문서 생성: 기존 개별 생성과 JSON·CSV 일치, 날짜 변경 시 revision 변경 확인.
- 자동 동기화 안정화 테스트와 기존 두 저장소 동기화 테스트를 포함한 전체 코어 테스트 89개 통과.
- Mac 및 iOS Simulator 빌드 성공. 버전 1.0, 빌드 5.
- 실제 Mac 앱 재실행 후 CPU: 19초 시점 42.7%, 1분 5초 시점 0.1%, 2분 24초 시점 0.0%.

## 해석 범위

변경 없는 쓰기 조정과 중복 계산은 확인하여 수정했으며, 관찰한 지속 CPU 부하는 해소되었다. 수정 전 샘플에서도 메인 스레드는 대부분 대기 상태였으므로, 사용자가 경험한 모든 간헐적 UI 멈춤의 원인이 동일하다고 단정하지 않는다. 일반 임시 폴더의 자동 동기화 테스트는 수정 전에도 통과했다. 실제 iCloud 환경에서의 장시간 사용 중 재발 여부는 추가 관찰이 필요하다.
