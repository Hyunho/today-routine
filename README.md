# 오늘의 루틴 · iPhone

SwiftUI와 SwiftData로 만든 개인 루틴 앱입니다. 데이터는 각 기기에 저장하며, 선택한 iCloud Drive 폴더로 아이폰·맥 사이 자동 동기화를 연결할 수 있습니다. 사이트 동기화는 지원하지 않습니다.

## 실행

1. `TodayRoutine.xcodeproj`를 Xcode에서 엽니다.
2. `TodayRoutine` 스킴과 iPhone 시뮬레이터를 선택합니다.
3. Run을 실행합니다. 최소 지원 버전은 iOS 17입니다.
4. 맥에서는 `TodayRoutineMac` 스킴과 My Mac을 선택합니다. 최소 지원 버전은 macOS 14입니다. 개발용 로컬 서명을 사용하며 App Store 배포 설정은 포함하지 않습니다.

실기기 설치 시 Xcode의 Signing & Capabilities에서 본인의 개발 팀과 사용 가능한 Bundle Identifier를 선택해야 합니다. 현재 프로젝트에는 개발 팀이나 인증서가 포함되어 있지 않습니다.

## 기능

- 오늘의 루틴과 예정 일감, 단계 체크, 완료·건너뜀·취소
- 매일·요일별 반복, 주간 횟수 목표, 그룹, 보관과 복원
- 수동 순서, 시간순, 그룹별 보기. 그룹 안은 시간순, 시간 미정은 마지막
- Apple 미리 알림 일감 편집과 완료, 타임블록 편집·겹침 안내·루틴 연결
- 한국 시간 기준 주간 완료 횟수
- 사용자 허용에 따른 기기 알림

알림은 앞으로 7일의 가까운 60개까지 예약하며 앱 활성화와 변경 시 갱신합니다. 7일 이상 앱을 열지 않으면 다음 알림이 자동 연장되지 않습니다. 주간 횟수 목표 루틴은 자동 알림 대상에서 제외됩니다. 집중 모드 등 운영체제 설정에 따라 알림 표시가 달라질 수 있습니다.

첫 실행은 빈 목록입니다. 기존 웹사이트 데이터는 복사하지 않습니다. 앱 삭제 시 데이터가 사라질 수 있으며 OS 백업은 사용자의 설정에 따릅니다.

## 검증

2026-10-02: 기존 20개 핵심 테스트와 iPhone UI 5개를 포함해 동기화 검사를 확장했습니다. [동기화 검증](docs/sync-verification.md)을 참고하세요. [상세 검증과 구현 판단](docs/verification-2026-10-02.md)을 참고하세요.

공유 모델·저장소·일정 규칙 테스트:

```sh
swift test --build-system native --scratch-path /private/tmp/today-routine-tests
```

시뮬레이터 UI 테스트:

```sh
xcrun simctl list devices available
xcodebuild -project TodayRoutine.xcodeproj -scheme TodayRoutine \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  -derivedDataPath /private/tmp/today-routine-ios-build test CODE_SIGNING_ALLOWED=NO
```

시뮬레이터 이름은 설치된 기기에 맞게 바꿉니다. 빌드 산출물은 `/private/tmp`를 사용해 Documents 폴더의 Finder 확장 속성이 테스트 번들 서명에 영향을 주지 않게 합니다.

실제로 실행할 로컬 Mac 앱은 `python3 scripts/build_mac_local.py`로 빌드합니다. 개발 인증서로 서명하여 업데이트 후에도 미리 알림 개인정보 권한에서 같은 앱으로 식별되도록 합니다. `CODE_SIGNING_ALLOWED=NO` 빌드는 실행용으로 사용하지 않습니다. 인증서가 여러 개면 `--identity`로 지정합니다. 이 명령은 기존 로컬 앱의 데이터 위치를 유지하도록 샌드박스 없이 서명하며, 배포용 샌드박스 설정과 별도로 사용합니다.
서명된 실행 앱은 `~/Applications/TodayRoutineMac.app`에 설치하고 해당 경로에서 실행합니다. 임시 폴더의 앱은 macOS 권한 관리에서 앱 식별자로 조회되지 않을 수 있습니다. 현재 사용자 실행 경로도 이 설치 경로입니다.

UI 테스트는 독립 저장 파일을 사용하므로 일반 앱의 사용자 데이터를 초기화하지 않습니다.

프로젝트 파일 재생성: `python3 scripts/generate-project.py`. 외부 패키지를 내려받지 않습니다.

## 범위

루틴 알림은 설정의 **기본 알림 사용**에서 한 번에 켤 수 있습니다. 시간이 지정된 루틴은 정시 또는 5·10·30분 전 알림을 따르며, 각 루틴은 기본 설정·별도 시간·끄기를 선택할 수 있습니다. 기존 개별 설정은 유지되며 **기존 루틴에 기본 설정 일괄 적용**을 확인하면 예외가 제거됩니다. 알림 제외 시간은 개별 알림에도 적용합니다. 기본값과 예외는 기기별로 관리하며, 캘린더와의 중복 알림 제어는 아직 제공하지 않습니다.

App Store·TestFlight 배포, TickTick, 웹 동기화, 위젯, 실시간 활동은 이번 버전에 포함하지 않습니다. 실기기 설치와 실기기 알림 전달은 별도 서명·기기 환경에서 검증해야 합니다.

## iCloud Drive 자동 동기화

1. 파일 앱 또는 Finder에서 iCloud Drive 안에 **빈 전용 폴더**를 만듭니다.
2. 앱의 설정 → iCloud Drive 폴더 → 동기화 폴더 선택에서 그 폴더를 선택합니다.
3. 다른 기기에서도 같은 Apple 계정의 같은 폴더를 선택합니다. 기존 기기 기록은 UUID별로 합쳐지며, 같은 이름의 별개 루틴은 자동 합치지 않습니다.
4. 폴더 저장 완료는 로컬 폴더에 파일을 썼다는 의미입니다. 상대 기기에서 실제 적용 영수증을 받으면 확인 상태가 바뀝니다.

앱이 활성 상태일 때 변경과 파일 알림을 약 0.5초 동안 묶어 확인합니다. 보조 확인은 15초에서 시작해 변경이 없으면 최대 120초까지 간격을 늘립니다. 이미 처리한 파일은 메타데이터를 비교해 변경분만 읽고, 과거 CSV 기준 문서는 하나씩 처리합니다. 수동 동기화는 전체 파일을 다시 검증합니다. iCloud 업로드·다운로드 시간은 별도이며 앱이 정지되면 즉시 반영을 보장하지 않습니다. 오프라인 변경은 기기의 영속 전송 대기열에 남고 연결이 복구되면 재시도합니다. 알림 사용 여부는 기기별입니다.

### CSV 직접 편집

설정의 **최신 루틴 CSV**에서 루틴별 파일 위치를 확인합니다. 맥은 기본 연결 앱으로 열고, 아이폰은 미리보기를 제공합니다. 아이폰에서 수정할 때는 파일 앱의 **같은 원본 파일**을 편집합니다. Numbers·Excel 자체 문서 형식이 아닌 UTF-8 CSV로 저장해야 합니다.

```csv
날짜,물 마시기,스트레칭,독서
2026-10-01,TRUE,TRUE,FALSE
2026-10-02,TRUE,FALSE,FALSE
```

- TRUE는 완료, FALSE는 미완료입니다. 영문 대소문자는 구분하지 않습니다.
- 날짜 행 추가가 가능합니다. 빈 셀·빠진 행·빠진 열은 삭제나 미완료 명령이 아닙니다.
- 열 이름 변경·세부작업 추가는 앱에서 합니다. 잘못된 날짜, 중복 날짜, 잘못된 값은 해당 파일 전체를 보류합니다.
- 단계가 없으면 `날짜,완료`를 씁니다. 과거에만 존재한 단계는 과거 열로 보존하며 해당하지 않는 날짜의 셀은 비웁니다.
- 같은 셀을 앱에서도 수정했으면 설정에서 앱 값 유지 또는 CSV 값 적용을 선택합니다. 다른 셀은 병합합니다.
- 기존 CSV는 앱이 덮어쓰지 않습니다. 새 상태는 **새 버전 폴더**에 출력됩니다. 수정할 때마다 최신 CSV를 열어 주세요. 과거 파일의 이미 처리한 동일 내용은 다시 반영하지 않으며, 새 작업으로 재적용하려면 최신 파일을 사용해야 합니다.

폴더는 `space.json`, `changes/`, `tables/`, `receipts/`로 구성됩니다. `tables/<기기>/<버전>/<루틴>/루틴.csv` 옆의 `baseline.json`과 `manifest.json`은 ID·과거 단계·변경 기준이므로 직접 수정하거나 분리하지 마세요. JSON 변경 파일과 영수증도 앱이 관리합니다. 첫 버전에서는 자동 정리를 하지 않아 파일 수가 늘어납니다.

### 연결 해제와 복구

연결 해제는 기기 데이터와 폴더 파일을 삭제하지 않습니다. 나중에 같은 공간을 다시 선택하면 해제 중의 변경도 전달합니다. 다른 공간 ID의 폴더로 자동 갈아타지는 않습니다. 권한이 만료됐으면 같은 폴더를 다시 선택하세요. 형식이 다른 JSON, 손상 파일 또는 iCloud 충돌 사본이 있으면 기록을 유지하고 동기화를 보류합니다. 원본을 별도 복사해 보관한 뒤 문제 파일을 복원하고 다시 확인하세요.

SwiftData 데이터베이스는 각 앱의 로컬 Application Support에 유지됩니다. 최초 업그레이드 전에 기존 SQLite와 WAL·SHM이 있으면 `<저장파일>.pre-sync-v1/`에 함께 보관합니다. 복원은 앱을 종료한 상태에서 세 파일을 함께 다뤄야 합니다. 동기화 폴더 전체의 별도 백업도 권장합니다. JSON 이벤트 이력을 임의로 지우면 다른 기기의 늦은 변경이나 삭제 상태를 잃을 수 있습니다.

## 수신함 · 루틴 알림과 RSS

다섯 번째 **수신함** 탭에서 루틴 알림과 구독 글을 최신순으로 봅니다. **전체 / 루틴 알림 / 구독 글**로 골라 보거나 **나중에 읽기**만 표시할 수 있습니다. 항목을 열면 읽음으로 표시되며 루틴의 완료 상태는 바뀌지 않습니다.

- 구독 관리의 `+`에서 HTTPS RSS·Atom 피드 주소를 추가하거나 삭제합니다. 최초 한 번 **통합 브리핑**이 등록되며, 삭제하면 자동으로 재등록되지 않습니다.
- 글 상세에는 피드가 제공한 본문을 텍스트로 표시합니다. 이미지·영상이나 원문 전체를 가져오는 기능은 포함하지 않으며, 오른쪽 사이드바의 **웹으로 열기**로 기본 브라우저에서 확인할 수 있습니다.
- 북마크 버튼으로 **나중에 읽기**에 저장합니다. 구독을 삭제해도 저장한 글은 남습니다.
- 필터별 읽던 목록 위치를 기억해 탭 이동이나 앱 재실행 후 복원합니다. 상세 본문의 스크롤 위치는 저장하지 않습니다.
- 수신함에 들어갈 때 마지막 갱신 후 15분 이상이면 새 글을 가져옵니다. 새로고침 버튼이나 아래로 당기기로 직접 갱신할 수 있습니다. 실패하면 기존 글을 유지하고 구독 관리에 오류를 표시합니다.
- 일반 글은 구독별 최근 500개, 일반 루틴 알림은 최근 90일을 보관합니다. 나중에 읽기에 저장한 항목은 이 제한에서 제외됩니다.

루틴 알림은 앱이 미리 계산해 저장한 **예정 시각 기준 기록**입니다. 앱 활성화나 수신함 확인 시 시간이 지난 항목을 기록으로 옮깁니다. OS 알림이 실제 표시됐다는 뜻은 아니며, 알림 권한이 없어도 앱 안에서는 확인할 수 있습니다. 예정 시각 전에 루틴을 완료하거나 알림을 끄면 대기 기록을 취소합니다. 설치 전이나 미리 예약하지 않은 과거 기간을 소급 생성하지 않습니다. 현재 일감 알림은 포함하지 않습니다.

수신함은 각 기기의 Application Support에 독립 저장하며 기존 루틴 데이터베이스와 iCloud Drive 동기화에 영향을 주지 않습니다. **아이폰·맥 간 수신함 동기화, 앱 종료 중 RSS 수집, RSS 푸시 알림은 지원하지 않습니다.**

## 앱 버전 관리

아이폰·맥의 버전과 빌드 번호는 [`app-version.json`](app-version.json)에서 함께 관리합니다. 설정 → **앱 정보**는 실행 중인 앱 번들의 실제 번호를 표시합니다. 현재 기준은 **1.0 (빌드 1)**이며, 버전 번호 변경이 App Store 배포를 의미하지는 않습니다.

```sh
# 현재 번호 확인
python3 scripts/app_version.py
# 새 기능 버전으로 올리기: 빌드 번호도 1 증가하고 Xcode 프로젝트를 갱신
python3 scripts/app_version.py 1.1.0
# 버전은 그대로 두고 빌드 번호만 증가
python3 scripts/app_version.py --bump-build
# 빌드 번호를 명시적으로 지정 (현재보다 큰 값)
python3 scripts/app_version.py 1.1.1 --build 10
```

일반 빌드나 `python3 scripts/generate-project.py` 실행만으로 번호가 증가하지 않습니다. Xcode의 버전 값을 따로 수정하면 재생성 시 공용 파일의 값으로 돌아갑니다. 배포용 빌드마다 빌드 번호를 올리고, 사용자에게 전달할 기능 변경은 minor, 오류 수정은 patch, 호환되지 않는 큰 변경은 major를 올리는 방식으로 관리합니다. 변경 사항은 [`CHANGELOG.md`](CHANGELOG.md)에 기록합니다.

버전 관리 검증: `python3 -m unittest discover -s scripts -p test_app_version.py`.

## Apple 미리 알림 연동

일감 → **미리 알림 연결**에서 접근을 허용하고 표시할 목록을 선택합니다. 설정에서도 연결 화면을 열 수 있습니다. 일감은 선택한 Apple 미리 알림 목록의 항목만 표시하고 원본을 직접 읽고 수정합니다. 상단 `+`도 미리 알림을 추가합니다. **미리 알림 추가**로 선택한 쓰기 가능한 목록에 새 항목을 만들 수 있습니다. 연결하지 않았거나 쓰기 가능한 목록이 없으면 연결 화면에서 목록을 선택합니다. 미리 알림 접근 권한이 없으면 일감을 추가할 수 없습니다.

- 제목, 메모, 마감일, 완료 상태를 원본에 반영합니다. 반복·알림·우선순위 등 다른 속성은 보존합니다.
- 오늘 탭에는 선택한 날짜가 마감인 항목을 표시합니다. 시간은 앱의 한국 시간 기준입니다.
- 앱 활성화, EventKit 변경 알림, 수동 새로고침으로 갱신합니다. 앱이 종료된 동안 즉시 갱신을 보장하지 않습니다.
- 읽기 전용 목록은 조회만 가능하며, 권한 거부 시 시스템 설정에서 권한을 다시 허용해야 합니다.
- 목록 선택은 기기별 설정입니다. 연결 해제는 Apple 미리 알림 원본을 삭제하지 않습니다. 기존 iCloud Drive 파일 동기화에 미리 알림 복사본을 추가하지 않습니다.
- 원본이 외부에서 변경되면 오래된 편집 내용의 저장을 거절하고 안내합니다. 편집 화면을 닫고 최신 항목을 다시 열어 수정합니다.

### 내부 일감 기능 종료

이 버전부터 앱 자체의 일감 생성·편집·완료 기능을 제거합니다. **업데이트 후 앱을 열면 기존 내부 일감은 완료 여부와 관계없이 삭제됩니다.** 보관하거나 미리 알림으로 옮기지 않습니다. Apple 미리 알림 원본은 이 삭제 대상에 포함되지 않습니다.

내부 일감에 연결되어 있던 타임블록은 제목과 시간을 유지하고 연결만 해제합니다. 새 타임블록은 루틴에만 연결할 수 있습니다. 내부 일감 집중 기능은 제거하며 루틴·타임블록 집중은 유지합니다.

삭제 기록은 기존 폴더 동기화로 전달하며 오프라인에서는 전송 대기열에 보존합니다. 구버전 기기에서 보내는 내부 일감도 새 버전에서는 삭제하므로 **모든 기기의 앱을 업데이트해 주세요.** 과거 동기화 이력 파일과 사용자가 별도로 만든 백업 파일은 지우지 않습니다. 실제 기기 데이터 삭제는 이 버전의 앱을 실행할 때 이루어집니다.

## 피드 본문 서식

피드 읽기 화면은 Markdown 제목·강조·링크·목록·인용·코드 블록·표와 HTML/XHTML 본문 서식을 표시합니다. 목록 미리보기는 일반 텍스트를 사용합니다. 예전에 수집한 HTML 본문은 피드에서 새로고침하면 원문 서식으로 갱신되며 읽음·나중에 읽기 상태는 유지됩니다. 더 이상 피드에 포함되지 않은 과거 글은 원문에서 확인해야 합니다.

본문은 비영구 WebKit 보기에서 표시하며 피드의 스크립트·프레임·폼·외부 리소스 자동 로딩은 허용하지 않습니다. 웹 링크는 기본 브라우저로 엽니다. 외부 이미지와 동영상이 필요한 글은 오른쪽 사이드바의 웹으로 열기를 이용합니다.


## Apple 캘린더

캘린더 탭 → 캘린더 관리에서 접근 권한을 허용하고 표시할 캘린더를 선택합니다. 날짜별 일정을 읽기 전용으로 표시하며, 루틴을 자동 등록하거나 원본 일정을 변경하지 않습니다. 일정 시간은 기기의 현지 시간대를 사용합니다. 캘린더 선택은 기기별 설정이고 Apple 계정의 일정 동기화는 시스템에서 처리합니다. 주간 기록은 전체 탭 → 주간 기록에서 확인합니다.

## Valley / 노마드코더 AX 인앱 브라우저

**전체 → 노마드코더 AX**에서 `https://nomadcoders.co/ax/dashboard`를 엽니다. 각 사이트는 별도의 페이지와 탐색 기록을 유지합니다.

**전체 → Valley**에서 `https://www.valley.town/space?tab=subscribed`를 엽니다. 뒤로 가기와 새로고침을 지원하고 탭 이동 시 페이지와 탐색 기록을 유지합니다. 로그인 쿠키는 기기별 WebKit 저장소에 보관됩니다. Safari의 로그인 상태와는 별개이며 사이트 정책에 따라 다시 로그인이 필요할 수 있습니다. 하단 탭은 **오늘 / 일감 / 피드 / 캘린더 / 전체**로 구성됩니다. **전체**는 루틴, 주간 기록, Valley, 설정 및 주요 화면으로 이동하는 네비게이션 페이지입니다. 루틴 관리는 **전체 → 루틴**에서 엽니다.

### 오른쪽 사이드바 · 웹으로 열기

Valley와 피드 글 상세 화면 오른쪽에 웹으로 열기 버튼을 표시합니다. 오른쪽 맨 위의 사이드바 버튼으로 펼치거나 숨길 수 있으며, 숨기면 본문이 해당 공간까지 넓어집니다. Valley는 현재 페이지를, 피드는 글의 원문 주소를 기본 브라우저로 엽니다. 유효한 HTTP/HTTPS 주소가 없으면 버튼이 비활성화됩니다.

## Mac Logseq 탭

Mac 하단 **Logseq** 탭에서 bilog의 저널·페이지·검색·블록 편집과 개별 Markdown 편집을 사용할 수 있습니다. 처음에는 **기존 그래프 열기** 또는 **Markdown 파일 열기**로 노트를 선택합니다. 이 앱에서 마지막으로 연 항목을 복원하며, 기존 독립 앱의 설정은 자동으로 가져오지 않습니다. 노트는 선택한 원본 폴더에 저장하고 루틴 동기화 데이터에 포함하지 않습니다.

그래프는 기존 자동 저장을 유지합니다. 개별 Markdown은 `Cmd+S`로 저장하며 탭 이동, 집중 화면 진입, 창 닫기와 종료 전에도 저장합니다. 외부 변경이나 저장 실패 시 이동을 취소하고 편집 내용을 유지합니다. Logseq가 활성인 창에서만 노트 단축키가 동작합니다. Logseq 탭은 넓은 편집 창을 사용하고 다른 탭으로 돌아가면 이전의 좁은 창 크기를 복원합니다.

편집기 소스는 `Packages/NativeLogseq`의 Git 서브모듈입니다. 새로 받은 저장소에서는 다음 준비가 필요합니다.

```sh
git submodule update --init --recursive
```

bilog 원격 저장소에 대한 SSH 접근 권한이 필요합니다. 업데이트 시 서브모듈 내부의 미커밋 변경을 먼저 확인하고, 원하는 커밋으로 이동해 검증한 뒤 상위 저장소의 참조를 갱신합니다. 빌드 과정에서 최신 버전으로 자동 변경하지 않습니다. 이전 버전으로 돌아갈 때도 상위 참조를 되돌린 뒤 위 명령으로 맞춥니다. 기존 Native Logseq 그래프와 개별 `.md` 파일을 지원하며 일반 Logseq의 모든 그래프 문법을 지원하는 것은 아닙니다.

## 타임라인 간격 JSON 설정

Mac의 **설정 → 타임라인 간격 · 설정 파일 → 설정 파일 열기**에서 사용자 설정을 편집합니다. 저장 후 **다시 불러오기**를 누르면 오늘 화면의 **타임라인 → 시간순**에 즉시 반영됩니다. 앱 시작 시에도 읽습니다.

동기화 폴더가 연결되어 있으면 해당 폴더의 `Config/list-layout.json`을 공용 설정으로 사용합니다. 이미 있는 공용 파일을 우선하며, 없을 때만 기존 로컬 설정을 복사합니다. 로컬 원본은 보존합니다. 다른 기기의 변경은 기존 자동 동기화 확인 주기에 맞춰 다시 읽습니다. iCloud 다운로드 중에는 현재 설정을 유지하며 공용 파일을 덮어쓰지 않습니다.

동기화 연결 전이나 연결 해제 후에는 앱의 Application Support 아래 `TodayRoutine/Config/list-layout.json`을 사용합니다. 일반 로컬 Mac 빌드에서는 `~/Library/Application Support/TodayRoutine/Config/list-layout.json`이며, 샌드박스 빌드에서는 컨테이너 안에 저장됩니다. 정확한 경로는 설정 화면에 표시됩니다. 저장소의 `Config/list-layout.json`은 복사해서 사용할 수 있는 기본값 예시이며, 앱은 이 저장소 파일을 직접 읽지 않습니다.

| 키 | 기본값 | 허용 범위 | 의미 |
|---|---:|---:|---|
| `itemMinHeight` | 54 | 44–240 | 항목의 최소 높이(pt). 글자·버튼·펼친 하위 항목에 필요한 높이는 보장합니다. |
| `durationHeightPerMinute` | 0.5 | 0–2 | 일정의 25분 초과 부분에 추가하는 분당 높이(pt). 0이면 시간에 따른 추가 높이가 없습니다. |
| `gapHeightPerHour` | 24 | 16–240 | 빈 시간 1시간당 높이(pt). 짧은 빈 구간도 시간에 비례하며 별도 최소 높이는 없습니다. |
| `itemSpacing` | 8 | 0–64 | 타임라인 요소 사이 여백(pt). 빈 시간 구간이 있어도 한 번만 적용됩니다. |
| `lineInset` | 8 | 0–32 | 시간 구분선 대비 항목 상하 선의 양끝 들여쓰기(pt). |

누락된 키, 숫자가 아닌 값, 허용 범위를 벗어난 값은 해당 키의 기본값을 사용합니다. JSON 문법 오류나 파일 읽기 오류는 전체 기본값으로 돌아가고 설정 화면에 안내합니다. 잘못된 파일을 자동으로 덮어쓰지 않습니다. 동기화 폴더의 설정은 같은 폴더를 연결한 기기에서 공유됩니다. 파일 열기와 재읽기 UI는 Mac에서 제공합니다.
